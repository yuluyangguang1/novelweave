# NovelWeave · 织文

AI 驱动的网文创作辅助工具。

## 定位
不是"一键生成"的玩具，而是**严肃的写作工作台**。帮助网文作者：
- 管理庞大的世界观（角色/势力/地点）
- 维护长篇一致性（防止人设崩塌、前文矛盾）
- 辅助日常写作（续写卡壳、润色、风格统一）

## 定位补充
- **关系账本与那张图** —— 角色间的边（关系类型、主体对客体的称谓、自哪章生效、到哪章失效）登记为结构化事实：侧栏「关系」页能登记、能改、能删，「看全图」给一张确定性的 SVG，连通成几块、谁在网外、哪几条边画不出来都写在图下那句话里。图、面板、续写上下文里的「活跃关系」、R15（端点或区间指向本书没有的东西）与 R34（账本自己说得通却画不出来的那几类：没有 id 或撞了同一个 id、两头同一人、区间填反、端点只靠名字连着）问的是 `src/core/relationgraph.js` **同一份**判据，不会出现画布上有条线而检查器说没这条边。库里存的边两头是角色 id 而不是模型给的那两个字（只有名字命中时算接上，但要报「改一次名字就断」）；落库四道闸：类型非空、两端都得是本书角色、自己不能连自己、起止章都得还在书里且顺序不能反。R19 另查称谓越界与双向矛盾。**没做**：力导向与拖拽缩放 —— 每帧抖一遍的图没法测，两次打开也不该长得不一样。
- **语义检索(可选)** —— 配置 embeddings 端点后,相关旧章按语义召回(硅基流动 bge 系列免费);未配置自动降级词频方案,写作永不因检索失败而中断。
- **信息控制与决策记录** —— 每章可声明"读者知道/主角知道/必须隐瞒/只能暗示"，隐瞒项自动成为续写硬禁令；创作决策当场记档、推翻留痕。
- **去 AI 味（可按书关闭）** —— 生成时把禁词与句式清单一起交给模型，写完由 R22 数密度与套路；侧栏「文体规则」页逐组开关、加本书自己的禁词。它只做可复现的统计，不评价文笔好坏。
- **节奏配额** —— R23/R24/R25 查「该有而没有」：整章没人开口、账本上没有任何变化点、连续几章同一种结尾钩子。同一段配额数字也会在写之前交给模型。一律 info：只提示，不触发自修补写，也不计入退出码。
- **复述与账本回查** —— R26 抓跨章/同章一字不差的整句（AI 续写最爱犯的毛病），R27 回查你登记给伏笔的「原文依据」是否真在正文里，R28 把已销毁的世界设定在往后章节里的复现报出来。这一批查的是「账本与正文对不上」，带原文引证、可点击跳转。
- **出场回查** —— R29 核对角色卡上的「首次出场章」与正文，R30 列出建档却从未被点名的角色与设定（僵尸卡清理），R31 挑出账本里亲密、正文里从未同框的关系边。一律 info：先声后人、侧面描写、转述式关系都是正当写法。
- **世界设定两层召回** —— 续写时先按正文关键词挑设定，再由**已经注入**的那几条把自己的同乡带进来（写「青雾山」就带出「山门」）。只有一层能做到的事绝不假装做了，也只到两层为止：再深就会顺着一串设定把整本世界书拖进上下文。`nw-context.mjs --lore --text "…"` 会逐条标出「第几层、被谁带出」。
- **这几格在界面上就填得进** —— 侧栏「世界设定」的表单能写触发关键词、副键（要不要与主键同时命中）与「在第几章被毁掉」，列表卡片上直接看得见，R28/R30、两层召回与三方合并读的也都是这几格。补上之前它们只有 CLI 写得进来：规则查得到，界面填不进。

- **文风基准可注入、可量化** —— 侧栏「文体规则」页勾定 1–2 章作基准，那几章的正文既在生成时注入 prompt 当样例（模仿笔法、不得复述情节），又被 R32 拿它的指纹当尺子逐章比对（句均字数 / 对话占比 / 段均句数 / 禁词密度四格，两格以上同时越界才报）。四处（注入行、面板、R32、`nw-style.mjs`）算的是同一个函数，不会出现「prompt 里承诺的基准，检查器按另一套口径查」。没勾基准就整条静默 —— 就近取的两章在长篇里恰好是漂得最远的，不能拿它冒充标准。恒为 info，永不拦生成。
- **卷级滚动压缩** —— 侧栏「卷」页把连续的几十章框成一卷、写一行摘要，前情摘要里「更早 N 章」那一段就改由这一行说话：180 章的书里，模型不再只看见一个计数。诚实口径是**斜率降到每卷一行，不是 O(1)** —— 卷多到装不下时再往前的折成「更早 N 卷、约 M 章已折」，折了几卷几章照实报。三条判据钉死：没写摘要的卷不盖章（那几十章退回逐章列出）、盖到本章之后的卷不注入（用了就是剧透）、起止章被删了就整卷不用（绝不按章号猜区间）。面板顶部那句缺口与 R33 报的是同一次计算，`nw-context.mjs` 末尾也会说这次吃到哪一层、还剩几章只有计数。
- **长短皆织** —— 长篇连载与短篇（3k–30k 字）同一套工作台；短篇模式自动换挡上下文与规则阈值，前情全量注入、钩子检查按"屏"评估。
- **工作流预设可分享** —— 侧栏「工作流」页把一本书调顺了的那三格（篇幅档 / 全篇字数目标 / 去 AI 味规则包）打成一个文件带给另一本书，反向导入也过同一道闸。**基准章刻意不进**：它记的是这本书里若干章的身份证，换一本书那些 id 就指不到东西。认不出的键、幽灵禁词组、坏数值各归各的说法，一条都不悄悄丢掉 —— 认不出就整份拒收，因为「分享者关掉了两组禁词，接收者以为已经生效」是这套功能唯一真正的失败模式。写库只有一条路：那张逐格「现在 / 预设 / 会不会变」的确认框，一格都没变就一个字都不写。CLI（`nw-workflow.mjs check`）只报告不改书，判据四处（core、界面、CLI、`schemas/workflow.v1.json`）出自同一份。

## 核心原则
- **作者掌控** — AI 只提供建议，作者决定最终文字
- **一致性优先** — 维护角色设定、世界规则、剧情线
- **写作流保护** — 任何 AI 辅助都不打断作者的沉浸感

## 技术路线
- 纯前端，零构建、零依赖 — 用静态服务器托管后打开即用，也可以直接双击 `index.html`
- BYOK（用户自带 API Key，浏览器直连 OpenAI 兼容接口）
- IndexedDB 本地存储（支持大文本）
- PWA：可离线、可安装（`manifest.webmanifest` + `sw.js`，图标由 `tools/make-icons.mjs` 程序生成）

## 本地运行与离线使用

任何静态服务器都行，例如：

```bash
python -m http.server 8080
# 或
npx serve .
```

然后访问 http://localhost:8080 。首次打开会先进设置页让你填入 API Key（Key 只存在本机浏览器）。

## Story Bible：与 agent 共享同一本书

织文的权威存储是浏览器里的 IndexedDB，但作品可以同时以**文件形态**存在
`.novelweave/` 目录里，供命令行 agent 直接读写：正文是 Markdown + frontmatter，
结构化状态（角色/世界/伏笔/时间线/状态快照）是 JSON。

- 格式定义：`schemas/story-bible.v1.json`
- 工作流预设（作者之间搬的那几格设置，与书存档分家）：`schemas/workflow.v1.json` + `skills/novelweave/references/workflow-preset.md`
- 字段说明与从 IndexedDB 的迁移映射：`skills/novelweave/references/schema-v1.md`
- 双端共用的实现：`src/core/text.js`、`src/core/bible.js`（浏览器与 Node 加载同一份代码）

## Agent 技能

`skills/` 是单一权威技能源，包含两个技能：

- `novelweave` —— 在已有 `.novelweave/` 的书上续写、修订、维护 Story Bible、走 `---CHANGES---` 提案
- `novelweave-continuity` —— 只读连续性检查，不改任何文件

安装（表驱动落位，仓库内不保存任何 agent 镜像目录）：

```bash
node tools/install.mjs --all --dry-run     # 先看会做什么
node tools/install.mjs --only=qoder        # 或 --all
node tools/install.mjs --status --json     # 查已装状态
node tools/install.mjs --uninstall         # 只删自己装的，指针块精确切除
```

权威源先物化到 `~/.novelweave/skills/`，再落位到各 agent 的官方目录；每个技能装完
自带 `scripts/`、`src/core/`、`schemas/`，可独立运行。

| Agent | 落位 | 说明 |
|---|---|---|
| Claude Code | `~/.claude/skills/` + `CLAUDE.md` 指针块 | 指针只追加，不动你原有内容 |
| Qoder | `~/.qoder/skills/` | |
| OpenClaw | `~/.openclaw/skills/` | 与 Claude Code 同规范 |
| Hermes | `~/.hermes/skills/writing/<skill>/` | 该 agent 要求 `category/` 嵌套与顶层 `version` |
| Codex CLI | `~/.codex/AGENTS.md` 指针块 | 无 skill 载体 |
| Cursor | 项目内 `.cursor/rules/novelweave.mdc` | 需在你的书项目目录下运行；在本仓库内运行会被拒绝 |
| WorkBuddy | `~/.workbuddy/skills/` | 布局按本机实测对齐；格式文档未公开，置信度标为 observed |
| ZCode | **不自动安装** | 本机未见用户级 skills 目录，只打印手动指引，不凭猜测写文件 |

## 仓库工具

`src/styles/app.css` 的设计令牌是照抄官网 `shared.css` 一份的（引它就不能离线、不能单独 clone），
所以抄来的东西会漂。比对靠这个脚本：

```bash
node tools/check-tokens.mjs                      # 自动在上一级找 shared.css
node tools/check-tokens.mjs --site ../yours/shared.css
node tools/check-tokens.mjs --app src/styles/app.css --json
```

单独 clone 时用 `--site` 或环境变量 `NW_SITE_SHARED_CSS` 指路。`--json` 是给机器读的：
stdout 里只有一个 JSON 对象，比对的是哪一份文件写在 `site` 字段里，不另起一行。

退出码 `0` 没有未处理漂移 / `1` 有漂移、同一份文件里自打嘴巴、或已知漂移表有过期条目 /
`2` 没找到对照文件 —— 找不到就说找不到，**跳过不等于通过**。
认可一条漂移要在 `KNOWN_DRIFT` 里写清理由，没理由的豁免一律不收。

# 路线图

README 只写已经能用的一切；这个文件写还没做的。

## 已完成

**阶段一 — 止血 + 定契约**

- 共享实现层 `src/core/text.js`、`src/core/bible.js`（UMD，浏览器与 Node 同一份代码）
- Story Bible v1：`schemas/story-bible.v1.json` + `skills/novelweave/references/schema-v1.md`
- 前端主流程修通：AI 工具箱、创建作品、四个侧栏面板、章节深链与刷新恢复、
  字数统计、注入面收口
- 续写的上下文召回：前文结尾 + 本章已写正文 + 按关键词触发的世界设定，带字节预算
- 零依赖测试：`node --test tests/*.test.mjs`

**阶段二 — 技能与连续性引擎**

- `src/core/rules.js`：10 条机器规则（死人出场、状态矛盾、伏笔未回收/逾期未收、
  payoff-before-setup、外貌区间违规、未登记实体、结构非法、引用断链、派生字段被手改、
  schema 非法先全停）与 LLM 补充诊断共用同一个 diagnostic 信封，但只有机器规则计入退出码
- `skills/novelweave/`（主编排）与 `skills/novelweave-continuity/`（只读校验），
  各带 `references/` 与 `assets/templates/`
- `scripts/nw-*.mjs`：io / validate / continuity / context / changes 五个零依赖 Node CLI，
  统一 stdout 出结果、stderr 出日志，退出码约定一致
- `---CHANGES---` 变更声明协议：解析 → 六道门禁 → 写 `pending.json` → **作者确认才落地**
- `tools/install.mjs` 表驱动分发：Claude Code、Qoder、OpenClaw、Hermes、WorkBuddy、
  Codex CLI、Cursor。仓库内不放任何 agent 镜像目录（有测试钉住）
- 验证：`node --test` 84 项全绿；装进 `~/.qoder/skills/` 后，在**另一个会话**里用自然语言
  提"帮我看看有没有前后矛盾"即被正确触发，只读跑通并准确报出"明长老死于 ch-001
  却在 ch-002 推门进内堂"，且未修改任何文件

**阶段三 — Web 端接上同一套状态**

已做到：

- IndexedDB 升到 v2：角色卡加 `status / died-in / first / aliases / appearance_tokens / enabled`，
  新增 `promises` / `timeline` / `suppressions` 三张表。老库就地升级，不破坏性迁移，
  缺字段在读取时补默认值
- 连续性面板：浏览器里跑**同一份** `rules.js`，诊断按严重度列出，点击可跳到该章并选中依据句；
  「豁免」按 fingerprint 写库留痕，之后不再重复提示但报告里仍计数
- 伏笔登记表：状态 / 分量 / 埋设章 / 回收章 / 期限 / 原文依据，是 promise 两条规则的数据来源
- 角色表单补齐 R1 与 R7 的输入：死亡章节、首次出场、别称、外貌特征区间
  （`特征词 | 从第N章 | 到第M章` 行式编辑）
- `.novelweave/` 导出与导入：优先 File System Access API，不支持时退回单文件目录树 JSON。
  导入走逐条三方比较（base 取自导出时写的 `meta/sync.json`），
  **两侧都改过的记录不自动选边**，本地版保留、文件版连同本地版落到 `conflicts/` 并额外下载一份
- 上下文用量可视化：每次续写显示注入/未注入哪几节、多少字节，被裁掉时给黄标警告；
  失败给「重试」按钮；写作温度可调并持久化
- 备份导入补齐（原先只有导出），且备份表清单改由数据层推导，避免加表时静默漏备份
- PWA：`manifest.webmanifest` + `sw.js` + 程序生成的图标。静态资源用 network-first
  （`app.css?v=1` 是个永不变化的参数，cache-first 会让改过的样式长期是旧的）；
  跨域与非 GET 请求一律不碰，BYOK 调用必须直达服务商

**补齐（阶段三之后）**

- 时间线面板：锚点的增删改（章 / 第几天 / 时辰 / 所属线 / 置信度）
- R6 `timeline-regression`：同一叙事线时间倒流。不同 `thread` 永不互比，
  `implied` 只出 info，闪回章跳过，回退后不回写最大值以免连锁误报
- 章节「出场 / 仅提及 / 地点」声明面板（编辑器工具栏的 cast 图标）。此前 R1 最强的那个信号
  只能由 agent 通过 `---CHANGES---` 写，作者自己反而声明不了
- 两处数据保真修复：导入按正文重算字数（不照抄文件里过期的 `x-words`，
  Web 端没有 `recount` 命令可修）；启动 self-heal 连每章 `word_count` 一起修
  （原先只修总数，漂移的章节会让 R16 长期误报、列表显示错数字）
- 状态矩阵（`states`）：IDB v3 一行一个「章节×实体」，主键 `章节|实体` 以便按记录
  合并；矩阵总览 + 分章六维编辑，字节数随输入实时刷新，超 3072 黄标。
  R2 的「快照与角色卡互斥」这一半此前在 Web 端从未被触发，现在有界面能填了
- 测试补了一条语法守卫：把 `index.html` 加载的每个脚本用 `vm.Script` 解析一遍。
  起因是 app.js 里多一个右括号让整页函数消失，而当时 110 项测试全绿——
  因为没有任何测试会把 app.js 当脚本解析

**界面设计对齐官网（yu.ai / shared.css）**

- 令牌照抄官网一份：纸墨黑 `21 14 7`、宣纸白 `243 237 226`、淡墨、朱砂 `242 99 78`、
  藤黄、胭脂；浅色主题走宣纸底 + 浓墨字 + 印泥红，跟随 `prefers-color-scheme`
- 语言：方角（圆角最多 2px）、发丝分隔线、无阴影；标题与正文用霞鹜文楷（衬线），
  导航与标签用等宽小字 + 字距 + 大写；列表用发丝线分隔的整块可点区域
- **代价（已知并接受）**：令牌是复制的，不是引用 `../shared.css`。因为本仓库是独立
  子模块，要能单独 clone 与离线当 PWA 用，引用官网根路径会两边都坏。
  官网改配色时这里要跟着改一次。
- 图标：界面**全面去除 emoji**，改为一期内联的 SVG sprite（`index.html` 里一组 24×24
  描线 `symbol`，`app.js` 用 `<use>` 引用）。emoji 是彩色位图字形，压在墨色配色上必然跳；
  图标不带颜色属性，描线由 CSS `stroke: currentColor` 继承，因此自动跟随主题与强调色。
  **刻意不引外部图标库**（同级 linger 用了 unpkg 的 lucide）——那会破坏离线 PWA 与零依赖。
- 新增守卫测试：`index.html` / `app.js` / `app.css` 里不允许出现 emoji 字形
- 样式自洽测试同时生效：每个用到的 class 必须有定义（图标相关的 `.icon` / `.sev-*` /
  `.usage-*` 等十来个新类都被它盯着）
- `theme-color` 按官网做法拆成深/浅两条，随系统切换，不再写死一个值

**写书流程补齐 — 前情摘要与正文版本**

- 上下文新增「前情摘要」一节：目标章之前最近 12 章的 `chapter.summary`。
  长篇靠它替代「回读全文」——这是跨章因果链断裂的直接对症，而不是又一个检查器。
  摘要有四行结构时**只注入「核心事件」一行**：位置 / 伤势 / 持有物由「分章状态快照」承载，
  伏笔由「未结线索」承载，12 章各 200 字全塞进来会把整份 12288 字节预算挤爆，
  被挤掉的恰好是「本章已有正文」。超出 12 章时在节里写明「更早 N 章未列出」，不静默丢。
- 摘要的可写入路径全通了：编辑器工具栏 scroll 图标开合摘要框；AI「总结本章」的结果
  多了「写回本章摘要」（原先只有「存为笔记」——笔记不进上下文，等于录了个没人读的事实）；
  有正文没摘要的章节在列表里标「摘缺」，摘要已填的按钮带一个朱点。
  长度实时计数按 schema 的 `maxLength: 400` 同口径（UTF-16 长度）；**超了只说不拦** ——
  作者的文本不该被界面截断，但导出后 `nw-validate` 会判违规，所以必须当场讲清楚。
- 正文版本快照（IDB v4 `revisions`）：每章最多 20 版，列出时间 / 来源 / 字数，可展开看全文，
  可一键回退。留底的四个点都是**覆盖式写入**：手动保存（Ctrl+S）、AI 整章润色替换、
  目录导入用文件版盖本地版、备份 JSON 导入按 id 盖库里记录。
  回退前也会先把屏幕上的文字留一版，所以回退本身也是可逆的。
  **刻意不给自动保存留版**：15 秒一发，噪声会淹掉有用的版本。
  与最新一版内容相同也不重复存（连点保存不会堆版本）。
- 版本历史只在本机，**不进 `.novelweave/` 导出**：目录那份的正解是 git，
  两边各存一套历史迟早互相打架。

顺带挖出并修掉的四个缺陷（都不是本来要做的事，但不修就是留着骗人）：

- **任何作者字段里的换行都会写坏导出文件**。frontmatter 是 YAML 极小子集，
  序列化时把值原样拼行，于是 `summary` 的第二行被解析器当成非法键 ——
  `parseFrontmatter` 抛错，agent 直接打不开这本书。而 AI 摘要天生多行，一写回就中。
  现在含换行的值走 `JSON.stringify` 转义成单行，读取侧对应地 `JSON.parse` 解回。
- **`chapterId` 指向不存在的章节时抛裸 TypeError**（`current.id`）。CLI 侧自己有前置校验，
  所以只有 Web 命中：章节在另一个标签被删、或导入改了 id 之后再点续写，
  AI 面板会永远停在「正在处理…」。现在核心层报清楚是哪个 id，界面上给可读失败。
- **编辑器工具栏的 AI 按钮渲染的是字符串不是图标**：`${t.icon}` 拿到的是 sprite 名，
  于是界面上明晃晃写着 `insert sparkle search note`。图标改造那一轮漏掉了这里，
  因为测试从不加载 app.js —— 补的是浏览器实测，不是新单测。
- 深链不再被首跑引导弹走：没配 API Key 时，从首页进来才跳设置页；
  刷新自己那一章或打开 `#/novel/.../chapter/...` 会留在原处，只弹一条提示。

**文体交接（nw-prose）**

- 起因是竞品分析里一个自打脸的地方：SKILL.md 早就写了「文笔诊断让位给文体类 skill」，
  但**没有任何机制** —— 于是续写完一章没人看文字质感，那一章带着 AI 味就进稿了，
  事后还答不出"这几章到底查过没有"。`scripts/nw-prose.mjs` 补的是管道，不是引擎：
  **它自己一行文笔判断都不做**，只做探测 → 交接 → 记录。
- `probe` 判"有没有能力"只看证据：CLI 要在 PATH 上；技能目录**还必须真有清单文件**。
  这条是被现实逼出来的 —— 同类里存在自称集成了去痕引擎、包内却只有一个 SKILL.md 的技能，
  按名字交接等于交给一个空壳。真机实测：`chinese-novelist` ✅ 可用、
  `novelwriter` 探到目录但判"清单文件一个都不存在"、`ironprose` 无二进制、`story-deslop` 未装。
- `packet` 给正文路径（**不内联正文**）、引擎用法、四条边界、以及跑完怎么 record。
  `--engine` 指定的引擎即使不可用也不换一个顶上：点名的失败比悄悄的替代有用。
- 台账 `continuity/prose.json` 每章只留最新一条，带 `contentHash`
  （与同步基线同一算法）。所以正文一改，结论自动变「过期」而不是继续冒充已查。
  `skipped` 必须带 `--note`、`issues` 必须带 `--findings`：跳过和有问题都是要能被追问的事实。
- 两处刻意的取舍：`status` **恒退 0**，不让 CI 因为"这台机器没装第三方技能"而红；
  台账**不进导出树、不参与作者哈希**，否则每跑一次文体检查就给相关章节造一次幻影冲突。
  两条都有测试钉住。

**散稿建档（nw-io adopt）**

- 竞品分析里排第 4 的短板其实是**入口问题**：没有 `.novelweave/` 的人根本用不上我们。
  `nw-io.mjs adopt <草稿目录> --title X` 把一堆 `.md`/`.txt` 收成一本合法的书。
- 三条硬保证：**草稿只读**（有测试逐文件比对源文件字节不变）；**章号不平移**
  （`第N章`/`001-`/`Chapter 7` 都认，楔子取 0、尾声取 max+1，这两个位置不动作者已有编号）；
  **判不出就拒建**（无章号又非楔子/尾声 → 退出码 2；重号 → 拒，因为章号现在就是 id，重号等于覆盖）。
- 新增 `src/core/draft.js`（UMD，纯解析不碰磁盘）：中文数字到阿拉伯数字、标题回填、
  重号/跳号/短到可疑的判定。整批按文件次序重编号的方案被我否掉了 ——
  把作者的「第5章」悄悄挪成「第3章」比不建档危险得多。
- 为此**放宽了契约**：`chapter.number` 的 `minimum` 从 1 改 0，R14 同步。
  这是有意的加宽（现有书不可能带 0），不是绕过校验 —— 当时 `nw-validate` 先把我自己
  建出来的书判成非法，是它对的。
- 顺带修掉一个真误报：共享抽取器 `NWRules.entityCandidates` 会把「路他已」「经看了」
  当人名（普通词恰好从姓字开始）。加了一道虚词闸，**只作用于姓氏式**，
  称谓式不过滤（林夫人/张道人都含「人」，一刀切会误杀）。
  R9 与 adopt 现在共用这一份抽取器，不会出现「建档看得见、检查报不出」。
- 显示层收口成一个 `Bible.chapterLabel`：`number 0` 渲染成「楔子」而不是「第0章」——
  后者喂给模型会被读成编号错误。

没做到（下一步）：

- 跨章瞬移、关系矛盾、物品失而复得、称谓越界四条规则仍未实现
- 矩阵在极窄屏下要横向滚动；章节很多时列会很长，没做「只看最近 N 章」的收敛
- 摘要只能手填或让 AI 生成后写回，**没做「按整卷滚动压缩」**：第 50 章续写时看到的
  仍只是第 38–49 章，更早的因果要靠作者自己留在各章摘要里
- 版本历史只有列表和整章回退，没有两版并排 diff；`word_count` 差异是唯一能看出改动大小的信号
- 文体台账只在目录侧：`nw-prose status` 看得到，织文界面看不到（它读 IndexedDB）。
  要在网页里显示，需要新库表 + 面板，并决定它是否参与三方合并
- 引擎目录是写死在 `nw-prose.mjs` 里的四个候选。装了新文体技能要改代码才认得，
  没有"作者自己登记引擎"的入口 —— 现阶段候选少，写死比造一个注册机制划算
- adopt 只把**章**建出来：角色状态、伏笔、时间线仍要靠人补或走 `---CHANGES---`。
  它不是"从正文反推整本 Story Bible"，那需要语义抽取，目前没有可靠且不猜的做法

## 已知未解

- **WorkBuddy**：本机实测布局为 `~/.workbuddy/skills/<name>/{SKILL.md,scripts/}`，
  frontmatter 顶层带 `version`，分发表已按此对齐。但它的格式文档没找到公开来源，
  置信度标的是 `observed-locally` 而不是 `verified`——换台机器可能要重看。
- **ZCode**：本机 `~/.zcode` 下没有用户级 skills 目录，技能只出现在
  `~/.zcode/cli/plugins/cache/<publisher>/<plugin>/<version>/skills/<skill>/` 这种插件路径里。
  伪造 publisher/version 目录属于猜测，所以安装脚本对它**只打印手动指引、不写文件**。
- 还有三条机器规则未实现（跨章瞬移、关系矛盾、称谓越界），
  以及时间线单调性检查因锚点密度不足而暂缓 —— 清单见
  `skills/novelweave-continuity/references/rules.md` 末尾「尚未实现的机器规则」。
  物品失而复得已由 R18 覆盖，但它只在状态矩阵记了的前提下生效，且恒为 info 不进退出码。
  别把这些当成"检查过了没问题"。
- 语义级矛盾（动机漂移、对白口吻跳人）只能靠 LLM，标 `source:"llm"` 且不进 CI 门禁。
- 世界书的 `recursive_scanning`（触发出的内容再触发别的内容）未实现，当前只做单层扫描。
- Web 与 `.novelweave/` 目录**双向已通**：导出铺出整棵树，导入按 `meta/sync.json` 的基线哈希
  做三方比较，两边都改过的记录不自动覆盖，而是把 file / local 两份一起写进 `conflicts/` 让作者选。
  没通的是冲突的**解决**界面——目前只能在文件或 git 里手工处理。

## 生成侧一期（已落地）

生成侧的第一步不是"一键成书"，而是把续写的质量与安全网做厚：

- **硬禁令节**（context.js）：死者名单与到期伏笔在生成前钉进 prompt 第一节，
  预算再紧最后才轮到它被裁。约束前置，比事后机检再改写便宜。
- **风格样例节**（context.js，`opts.style` 开启）：从目标章之前正文足量的最近章节
  取中段节选（中段是叙述稳定区，开头带承接、结尾带钩子，都不代表日常笔触），
  让模型模仿作者自己的句长与节奏。默认关闭；Web 续写已开启，CLI 走
  `nw-context --style`。
- **生成后自检**（`src/core/selfcheck.js`）：草稿在内存里过机器规则。自检跑两遍
  取基线 —— 书里既有的陈年问题不算草稿的账；基线外的新 error/warn 转成修订
  指令让模型自修一轮，修订稿与机检发现一起交给作者。info（R17）不触发自修轮。
  Web 续写已接线；自修失败时兜底交付原始草稿，自检通路任何异常都不吞稿。
- **R17 章末钩子**（rules.js）：结构信号级 —— 本章未新埋伏笔且结尾 300 字无
  悬念标记 → info。钩子质量无法机器判定，恒为 info，永不计入退出码。
- **模板库**：`assets/templates/golden-three.json`（黄金三章结构）与
  `genre-presets.json`（玄幻 / 都市 / 系统流 / 悬疑四题材预设），供起书向导
  与章纲生成引用。

尚未做：从零起书向导（nw-new）、大纲/拍点 schema、语义检索、批量成稿模式。
从零那一半要做成"分层确认的向导"，不是一键扔 50 章。

## 短篇支持一期（已落地）

织文织短文了。`book.format: "long" | "short"`（schema 可选字段，默认 long，
存量书零影响），短篇模式下自动换挡：

- **前情摘要不封顶**：长篇滚 12 章窗口；短篇全量列出 —— 体量小，连"回读"都省了
- **R17 阈值换挡**：短篇一章≈一到三屏，800 字门槛降到 300；钩子话术从
  "章末"换成"屏末"（短篇的生死在前三屏）
- **侧栏收敛**：短篇书隐藏时间线 / 状态矩阵入口（长篇的重型机械；数据仍在，
  导出照带）
- **新建作品规格选择**：长篇连载 / 短篇，一眼选定织物规格
- **模板**：`short-presets.json` —— 反转流 / 情感流 / 脑洞设定流三种结构、
  屏末钩子句式、3k–30k 三档字数预算

尚未做：短篇版从零向导（想法→梗概→成稿，生成侧二期的首发场景）、
平台字数档位适配提示（番茄 2 万 / 盐选 5 万的节奏建议）。

## 短篇从零向导（已落地 —— 生成侧二期首发）

- **AI 起书 · 短篇**（首页入口）：一句话想法 + 结构流派（反转/情感/脑洞）+ 篇幅档
  （3k-6k / 8k-15k / 20k-30k）→ LLM 生成结构化梗概（书名 / logline / 人物 / 章纲拍点）
  → **每项可直接改** → 确认后建档：书（format:short）+ 角色 + 带拍点摘要的空章节。
- 建档建的是骨架，不是成品：正文由作者逐章「续写」产出，天然带上硬禁令、
  文风样例与生成后自检 —— 从零生成的质量下限由既有安全网兜住。
- `parseConceptJSON` 容忍围栏与废话、缺字段拒绝建档（有测试钉住）。
尚未做：确认后的「连续生成 N 章」按钮（逐章自动续写+自检，每章可停）、
长篇版向导（卷纲层）。

## 前情摘要三级衰减（已落地 —— 长篇召回升级）

长篇不再硬切"更早 N 章未列出"。超出细摘要窗口的前情按距离衰减，语义检索上线前先保证锚点可见：

- **最近 12 章**：核心事件行（80 字）
- **再往前 24 章**：章名一行列出（网文章名通常自带事件，成本极低）——
  200 章的书续写第 201 章时，第 5 章起的每个事件锚点都在 prompt 里
- **更早**：只报数量（章名列表超长时折叠到 420 字）
- 短篇（cap=Infinity）保持全量细摘要不变

示例书升级为版本化：`demo_version` 标记内容版本，老用户的旧版示例书在
「载入示例书」时自动级联删除重灌（自己改过示例书的极端情况请先导出）。

## 相关旧章检索（已落地 —— 长篇召回第二级）

"相关旧章"节：按本章出场角色（声明或摘要/正文命中）在旧章正文中被提及的
次数打分，召回细摘要窗口之外、相关度最高的 3 章，每条带相关人物与该章摘要
节选。纯词频、无模型、无索引，usage 面板如实显示召回了哪几章。

- 空章节（待生成）的出场角色从拍点摘要识别 —— 摘要天然就是人物声明
- 上一章与细摘要窗口内的章不重复召回；短篇全量注入，不启用本节
- 语义检索（embeddings）仍是后续项：那时"相关"从词频升级为语义

## 长篇从零向导 + R18 物品规则（已落地）

- **AI 起书 · 长篇**（首页入口）：想法 + 卷数（2/3/5）→ 生成全书骨架
  （书名 / logline / 人物 / 世界设定 2-4 条 / 卷纲 / 首卷前 12 章章纲），
  每项可改，确认后建档：书 + 角色 + 世界设定 + **卷纲写入「写作笔记」**
  （不发明新存储）+ 带拍点的空章节。建档后同样可一键连续生成。
- **R18 物品失而复得**（rules.js）：以状态矩阵为准 —— 物品在「持有物」中
  连续缺席 ≥2 章后重新出现 → info（补记矩阵或补写失而复得的情节）。
  矩阵没记不等于物品不存在，恒为 info 永不进退出码。

仍在清单上：跨章瞬移与称谓越界（需要地点/称谓的结构化建模，纯文本启发式
误报率高，暂缓是对的）；关系图谱（需要 schema 扩展 relations）；
语义检索（embeddings）；EPUB 导出。

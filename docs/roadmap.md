# 路线图

README 只写已经能用的一切；这个文件写还没做的。

本文件按时间顺序累积，各节结尾的「尚未做」是**当时**的口径，后续落地不回改——
所以读单节会读到过期结论。**当前未做的清单以文末「待办清单」为准**，
那一节逐条对代码核对过。

**界面设计对齐官网（yu.ai / shared.css）**

- 令牌照抄官网一份：纸墨黑 `21 14 7`、宣纸白 `243 237 226`、淡墨、朱砂 `242 99 78`、
  藤黄、胭脂；浅色主题走宣纸底 + 浓墨字 + 印泥红，跟随 `prefers-color-scheme`
- 语言：方角（圆角最多 2px）、发丝分隔线、无阴影；标题与正文用霞鹜文楷（衬线），
  导航与标签用等宽小字 + 字距 + 大写；列表用发丝线分隔的整块可点区域
- **代价（已知并接受）**：令牌是复制的，不是引用 `../shared.css`。因为本仓库是独立
  子模块，要能单独 clone 与离线当 PWA 用，引用官网根路径会两边都坏。
  官网改配色时这里要跟着改一次。
- 图标：界面**全面去除 emoji**，改为一期内联的 SVG sprite（`index.html` 里一组 24×24
  描线 `symbol`，`app.js` 用 `<use>` 引用）。emoji 是彩色位图字形，压在墨色配色上必然跳；
  图标不带颜色属性，描线由 CSS `stroke: currentColor` 继承，因此自动跟随主题与强调色。
  **刻意不引外部图标库**（同级 linger 用了 unpkg 的 lucide）——那会破坏离线 PWA 与零依赖。
- 新增守卫测试：`index.html` / `app.js` / `app.css` 里不允许出现 emoji 字形
- 样式自洽测试同时生效：每个用到的 class 必须有定义（图标相关的 `.icon` / `.sev-*` /
  `.usage-*` 等十来个新类都被它盯着）
- `theme-color` 按官网做法拆成深/浅两条，随系统切换，不再写死一个值

**写书流程补齐 — 前情摘要与正文版本**

- 上下文新增「前情摘要」一节：目标章之前最近 12 章的 `chapter.summary`。
  长篇靠它替代「回读全文」——这是跨章因果链断裂的直接对症，而不是又一个检查器。
  摘要有四行结构时**只注入「核心事件」一行**：位置 / 伤势 / 持有物由「分章状态快照」承载，
  伏笔由「未结线索」承载，12 章各 200 字全塞进来会把整份 12288 字节预算挤爆，
  被挤掉的恰好是「本章已有正文」。超出 12 章时在节里写明「更早 N 章未列出」，不静默丢。
- 摘要的可写入路径全通了：编辑器工具栏 scroll 图标开合摘要框；AI「总结本章」的结果
  多了「写回本章摘要」（原先只有「存为笔记」——笔记不进上下文，等于录了个没人读的事实）；
  有正文没摘要的章节在列表里标「摘缺」，摘要已填的按钮带一个朱点。
  长度实时计数按 schema 的 `maxLength: 400` 同口径（UTF-16 长度）；**超了只说不拦** ——
  作者的文本不该被界面截断，但导出后 `nw-validate` 会判违规，所以必须当场讲清楚。
- 正文版本快照（IDB v4 `revisions`）：每章最多 20 版，列出时间 / 来源 / 字数，可展开看全文，
  可一键回退。留底的四个点都是**覆盖式写入**：手动保存（Ctrl+S）、AI 整章润色替换、
  目录导入用文件版盖本地版、备份 JSON 导入按 id 盖库里记录。
  回退前也会先把屏幕上的文字留一版，所以回退本身也是可逆的。
  **刻意不给自动保存留版**：15 秒一发，噪声会淹掉有用的版本。
  与最新一版内容相同也不重复存（连点保存不会堆版本）。
- 版本历史只在本机，**不进 `.novelweave/` 导出**：目录那份的正解是 git，
  两边各存一套历史迟早互相打架。

顺带挖出并修掉的四个缺陷（都不是本来要做的事，但不修就是留着骗人）：

- **任何作者字段里的换行都会写坏导出文件**。frontmatter 是 YAML 极小子集，
  序列化时把值原样拼行，于是 `summary` 的第二行被解析器当成非法键 ——
  `parseFrontmatter` 抛错，agent 直接打不开这本书。而 AI 摘要天生多行，一写回就中。
  现在含换行的值走 `JSON.stringify` 转义成单行，读取侧对应地 `JSON.parse` 解回。
- **`chapterId` 指向不存在的章节时抛裸 TypeError**（`current.id`）。CLI 侧自己有前置校验，
  所以只有 Web 命中：章节在另一个标签被删、或导入改了 id 之后再点续写，
  AI 面板会永远停在「正在处理…」。现在核心层报清楚是哪个 id，界面上给可读失败。
- **编辑器工具栏的 AI 按钮渲染的是字符串不是图标**：`${t.icon}` 拿到的是 sprite 名，
  于是界面上明晃晃写着 `insert sparkle search note`。图标改造那一轮漏掉了这里，
  因为测试从不加载 app.js —— 补的是浏览器实测，不是新单测。
- 深链不再被首跑引导弹走：没配 API Key 时，从首页进来才跳设置页；
  刷新自己那一章或打开 `#/novel/.../chapter/...` 会留在原处，只弹一条提示。

**文体交接（nw-prose）**

- 起因是竞品分析里一个自打脸的地方：SKILL.md 早就写了「文笔诊断让位给文体类 skill」，
  但**没有任何机制** —— 于是续写完一章没人看文字质感，那一章带着 AI 味就进稿了，
  事后还答不出"这几章到底查过没有"。`scripts/nw-prose.mjs` 补的是管道，不是引擎：
  **它自己一行文笔判断都不做**，只做探测 → 交接 → 记录。
  （这条界守到 I 节为止：现在它多了一个内置兜底包，`lint` 只数禁词密度与句式套路，仍不评价文笔。）
- `probe` 判"有没有能力"只看证据：CLI 要在 PATH 上；技能目录**还必须真有清单文件**。
  这条是被现实逼出来的 —— 同类里存在自称集成了去痕引擎、包内却只有一个 SKILL.md 的技能，
  按名字交接等于交给一个空壳。真机实测：`chinese-novelist` ✅ 可用、
  `novelwriter` 探到目录但判"清单文件一个都不存在"、`ironprose` 无二进制、`story-deslop` 未装。
- `packet` 给正文路径（**不内联正文**）、引擎用法、四条边界、以及跑完怎么 record。
  `--engine` 指定的引擎即使不可用也不换一个顶上：点名的失败比悄悄的替代有用。
- 台账 `continuity/prose.json` 每章只留最新一条，带 `contentHash`
  （与同步基线同一算法）。所以正文一改，结论自动变「过期」而不是继续冒充已查。
  `skipped` 必须带 `--note`、`issues` 必须带 `--findings`：跳过和有问题都是要能被追问的事实。
- 两处刻意的取舍：`status` **恒退 0**，不让 CI 因为"这台机器没装第三方技能"而红；
  台账**不进导出树、不参与作者哈希**，否则每跑一次文体检查就给相关章节造一次幻影冲突。
  两条都有测试钉住。

**散稿建档（nw-io adopt）**

- 竞品分析里排第 4 的短板其实是**入口问题**：没有 `.novelweave/` 的人根本用不上我们。
  `nw-io.mjs adopt <草稿目录> --title X` 把一堆 `.md`/`.txt` 收成一本合法的书。
- 三条硬保证：**草稿只读**（有测试逐文件比对源文件字节不变）；**章号不平移**
  （`第N章`/`001-`/`Chapter 7` 都认，楔子取 0、尾声取 max+1，这两个位置不动作者已有编号）；
  **判不出就拒建**（无章号又非楔子/尾声 → 退出码 2；重号 → 拒，因为章号现在就是 id，重号等于覆盖）。
- 新增 `src/core/draft.js`（UMD，纯解析不碰磁盘）：中文数字到阿拉伯数字、标题回填、
  重号/跳号/短到可疑的判定。整批按文件次序重编号的方案被我否掉了 ——
  把作者的「第5章」悄悄挪成「第3章」比不建档危险得多。
- 为此**放宽了契约**：`chapter.number` 的 `minimum` 从 1 改 0，R14 同步。
  这是有意的加宽（现有书不可能带 0），不是绕过校验 —— 当时 `nw-validate` 先把我自己
  建出来的书判成非法，是它对的。
- 顺带修掉一个真误报：共享抽取器 `NWRules.entityCandidates` 会把「路他已」「经看了」
  当人名（普通词恰好从姓字开始）。加了一道虚词闸，**只作用于姓氏式**，
  称谓式不过滤（林夫人/张道人都含「人」，一刀切会误杀）。
  R9 与 adopt 现在共用这一份抽取器，不会出现「建档看得见、检查报不出」。
- 显示层收口成一个 `Bible.chapterLabel`：`number 0` 渲染成「楔子」而不是「第0章」——
  后者喂给模型会被读成编号错误。

没做到（下一步）：

- 跨章瞬移、称谓越界两条规则仍未实现（需要地点距离与说话人归属的结构化建模，
  纯文本启发式误报率高）。关系矛盾已由 R19 覆盖、物品失而复得已由 R18 覆盖
- 矩阵在极窄屏下要横向滚动；「只看最近 N 章」的收敛已由 R 节做掉（一页 40 章 + 往前翻页 + 整本一起看），列不再无限长。剩下的是**一页数得清**要靠加宽面板或 sticky 章列，没做
- 摘要只能手填或让 AI 生成后写回，**没做「按整卷滚动压缩」**。三级衰减（12 细 /
  24 章名 / 更早报数）与语义检索上线后，更早的锚点不再是黑的，但**卷级摘要**仍缺：
  500 万字量级要靠逐章章名撑前情，成本会随章数线性涨
- 版本历史只有列表和整章回退，没有两版并排 diff；`word_count` 差异是唯一能看出改动大小的信号
- 文体台账只在目录侧：`nw-prose status` 看得到，织文界面看不到（它读 IndexedDB）。
  要在网页里显示，需要新库表 + 面板，并决定它是否参与三方合并
- 引擎目录是写死在 `nw-prose.mjs` 里的四个外部候选（外加 I 节那个内置兜底包）。装了新文体技能要改代码才认得，
  没有"作者自己登记引擎"的入口 —— 现阶段候选少，写死比造一个注册机制划算
- adopt 只把**章**建出来：角色状态、伏笔、时间线仍要靠人补或走 `---CHANGES---`。
  它不是"从正文反推整本 Story Bible"，那需要语义抽取，目前没有可靠且不猜的做法

## 已知未解

- **WorkBuddy**：本机实测布局为 `~/.workbuddy/skills/<name>/{SKILL.md,scripts/}`，
  frontmatter 顶层带 `version`，分发表已按此对齐。但它的格式文档没找到公开来源，
  置信度标的是 `observed-locally` 而不是 `verified`——换台机器可能要重看。
- **ZCode**：本机 `~/.zcode` 下没有用户级 skills 目录，技能只出现在
  `~/.zcode/cli/plugins/cache/<publisher>/<plugin>/<version>/skills/<skill>/` 这种插件路径里。
  伪造 publisher/version 目录属于猜测，所以安装脚本对它**只打印手动指引、不写文件**。
- 还有两条机器规则未实现（跨章瞬移、称谓越界），

  （这里曾经挂着一条「世界书 `recursive_scanning` 声明 true 而引擎只做单层」，

## 生成侧一期（已落地）

生成侧的第一步不是"一键成书"，而是把续写的质量与安全网做厚：

- **硬禁令节**（context.js）：死者名单与到期伏笔在生成前钉进 prompt 第一节，
  预算再紧最后才轮到它被裁。约束前置，比事后机检再改写便宜。
- **风格样例节**（context.js，`opts.style` 开启）：从目标章之前正文足量的最近章节
  取中段节选（中段是叙述稳定区，开头带承接、结尾带钩子，都不代表日常笔触），
  让模型模仿作者自己的句长与节奏。默认关闭；Web 续写已开启，CLI 走
  `nw-context --style`。
- **生成后自检**（`src/core/selfcheck.js`）：草稿在内存里过机器规则。自检跑两遍
  取基线 —— 书里既有的陈年问题不算草稿的账；基线外的新 error/warn 转成修订
  指令让模型自修一轮，修订稿与机检发现一起交给作者。info（R17）不触发自修轮。
  Web 续写已接线；自修失败时兜底交付原始草稿，自检通路任何异常都不吞稿。
- **R17 章末钩子**（rules.js）：结构信号级 —— 本章未新埋伏笔且结尾 300 字无
  悬念标记 → info。钩子质量无法机器判定，恒为 info，永不计入退出码。
- **模板库**：`assets/templates/golden-three.json`（黄金三章结构）与
  `genre-presets.json`（玄幻 / 都市 / 系统流 / 悬疑四题材预设），供起书向导
  与章纲生成引用。

尚未做：从零起书向导（nw-new）、大纲/拍点 schema、语义检索、批量成稿模式。
从零那一半要做成"分层确认的向导"，不是一键扔 50 章。

## 短篇支持一期（已落地）

织文织短文了。`book.format: "long" | "short"`（schema 可选字段，默认 long，

## G. 导入侧的决策与关系边(已落地 —— 顺手挖出一个更严重的崩)

原待办写的是「关系边永远判 `new` 盖掉本地」。核对代码后真相更糟:

- `authorProjection` 根本没有 `relation`/`decision` 两个分支,所以比较器一碰到
  非空的 `relations.json` 就抛 `未知投影类型 relation`(`node -e` 探过,改前三者全抛)。
  这句 `await buildMergePlan(...)` 没有在 `importNovelweave` 的 try 里,而它在
  `ACTIONS` 派发器里是条没人接的 promise —— **于是「导入 .novelweave/」对任何
  登记过关系的书都是点下去毫无反应**,不是覆盖错数据,是压根没跑完。
- `current` 只组装了 6 个 store,`relations`/`decisions` 恒空:即便不抛,也是整表判 `new`。
- 两条 bucket 与取数分散在 app.js 与 project.js 两处、且 app.js 无法在 Node 里执行,
  所以 195 项测试全绿也照不出来。

修法(全部落在可测的一层):

## I. 去 AI 味文体规则包(P0–P3 已落地 —— 把清单变成能数、能关的东西)

来源同样是 2026-09-20 那份竞品对照。此前"去 AI 味"在这仓里只有两句口头约定:
SKILL.md 说"判断交给文体类 skill",`nw-prose` 说"我不动手"。结果是**没有任何一处真的数过**
一章里有多少"仿佛""心里五味杂陈",而本机装了外部文体引擎的机器又是少数。
这一条把清单变成一份可统计、可关闭、可导出的规则包。

**P0 包本体**(`src/core/stylepack.js`,新模块):8 个词组(心理直说 / 比喻引导词 / 眼神套路 /
抽象概括 / 转折套话 / 反问铺垫 / 副词堆叠 / 段尾金句)+ 5 条句式套路(同开头连击 /
连续无对话段 / 二元对照句 / 三短句连击 / 破折号插入语)。四个出口:
`lint`(命中与证据,每条带原文 `start/len` 所以点得回去)、`verdict`(每千字 ≥3 或句式 ≥2 类为 warn,
≥1.5 为 info,正文不足 500 字不评)、`promptBlock`(生成前给模型看的那份清单,有长度预算)、
`optsFrom`(读本书开关)。**开关做在包里面而不是三个调用方各自判断**:`lint` 与 `promptBlock`
拿到 `enabled:false` 自己返回空,少一处记得判断就少一处不一致。

**P1a 接线**:新模块要同时进四张手写的加载表(`index.html`、`sw.js` 的 `PRECACHE`、
`tests/_load.mjs`、`scripts/lib/book.mjs`),漏一处的表现不是报错而是**工厂拿到 undefined 后静默不响**
—— UMD 的实参依赖是加载期取的。仓库原有两条守卫只看得到 `index.html`,所以这轮的真正增量是守卫:
`每张加载表里，UMD 依赖都排在用它的模块之前`改成**从源码里反推依赖**(`factory(root.NWxxx, …)` 与
`else root.NWxxx = mod;`),新模块不必回头改测试;另加两条(缓存条目必须同时进壳、core 下不许有孤儿/幽灵)。
反验用 `falsify-load.mjs` 三处变异(从 CLI 表里删掉一条依赖 / 调乱顺序 / PRECACHE 单边加条目),三处都报红。

**P1b R22 `ai-flavor`**(规则数 16 → 17,首页声明跟着 `RULES` 算):它只是把包接进 `runRules`,
判据、证据、豁免全走既有那套(`diag` 指纹、suppression 可豁免本章)。这是仓里第一条查腔调而非查事实的
机器规则,所以 `detail` 里明写"误报了关掉那组即可,不要拿它当门禁"。
**P1c 写之前也带着它**:`llm.js` 的 `buildContinueContext` 在写作要求后面接 `antiAiRules(book)`,
模型一开始就按约束写,比事后按诊断改写少烧一轮 API。两处共用同一份 `promptBlock`,
不会出现"prompt 里禁 A、规则里查 B"。

**P2 CLI 兜底引擎**:`nw-prose.mjs` 多一个 `lint` 子命令(这文件里唯一自己动手的),
`ENGINES` 多一条 `kind: 'builtin'`,永远 `usable`。**它不抢位**:`recommended` 与 `packet`
仍优先给真实的外部引擎,内置包排在最后。台账区分 `clean` 与 `skipped`:包被关掉、正文不足 500 字
都记 `skipped` 带原因 —— "没评"写成"评了没问题"正是这仓反复犯的那类错。`status` 页脚在没外部引擎时

**P3 作者可改包**:包不再是写死在代码里的。`book.stylePack`(`enabled` / `disabled[]` / `extraBanned[]`)
落进 novels 行(schema 加了可选属性),`buildCtx` 原样过桥,`project.js` 导出与 `parseFileMap` 导入都带着走,
侧栏新增「文体规则」页:整包开关 + 八组逐个开关(从 `GROUPS` 现生成,加一组自动多一个开关)+ 本书额外禁词。

## J. 正向节奏配额(P0–P3 已落地 —— 规则表里第一批「该有而没有」)

竞品那一侧最大的缺口:R1–R22 全在查「不能错 / 别这么写」,没有一条问「这一章读起来有没有理由翻下一页」。
借鉴的是 chinese-novelist-skill 的「每章偿旧提新 / 连续 500 字无冲突 / 对话占比 / 同质钩子」那组配额,
但**只搬机器数得出来的那几条**:

- `src/core/tension.js`(新包,与 `stylepack.js` 同构):`dialogueSpans`(成对引号内的原文段)、
  `stats`(对话占比 + 最长纯叙述连段,带偏移)、`hookKind`(结尾 120 字只认问句与突转两类)、
  `QUOTAS`(长/短两档门槛)、`tally`(未收/逾期/最久的伏笔三个数字)、`promptBlock`(写之前那段配额)。
  段落切分**复用** `stylepack.js` 的 `paragraphs`(为此把它导出),不留第二套切法。
- **R23 `dialogue-ratio`**(章级):占比 <8% 或连续 ≥800 字没人说话才报,整章不足 1500 字不评。
  **R24 `chapter-no-change`**(章级):伏笔 setup/payoff、状态矩阵实质变化、信息差揭示,
  四者皆无才算平章;**全书一条登记都没有时整条规则不输出**。
  **R25 `same-hook-streak`**(书级):同一种钩子连续 ≥3 章,一段只报一条,落在段首章上以便 `--from/--to` 筛到。

  等于命令模型为凑配额去补对话、补伏笔 —— 那是配额规则最坏的用法。这条决定比"哪一档更严"重要,
  所以它不是实现细节而是规格。
- **P2 写之前**:`llm.js` 的 `buildContinueContext` 在写作要求与去 AI 味之间插入 `tensionRules(ctx)`。
  排在去 AI 味之前是因为现有测试钉着「清单必须在整份 prompt 最末尾」;配额块带的是**账本里的真数字**

- **P3 接线**:四张加载表加 `tension.js`(`sw.js` 的 `VERSION` 升到 `nw-v5`,同 v4 的理由)、
  首页声明 17 → 20 条(由 `RULES` 算出,守卫盯着)、`ALIAS` 一次补齐 R17–R25。
  补 `ALIAS` 时发现的既有缺陷:它停在 R16,所以 `--rules R17`…`R22` **一直**静默解析成空,
  使用者拿到一份空报告还以为没问题。新守卫 `CLI 的 R 编号别名表覆盖每一条已实现规则` 把它钉住,

## K. 复述与账本回查(P0–P4 已落地 —— 第三批:查「记的与写的对不上」)

R1–R19 查「不能错」,R20/R21/R22 查「别这么写」,R23/R24/R25 查「该有而没有」。
这一批补上第四种问法:**你在账本里登记的东西,正文里还认不认**。三条都只读界面填得出、
CLI 写得出、导出去还带得回来的字段 —— 上一批的教训是,判据一旦建立在填不出的字段上,规则就是死的。

- **R26 `repeated-sentence`**(书级):同一个长句被逐字写两遍。句子取自 `NWStylePack` 的切分器
  (与 R22 同一把刀,为此把 `sentences` 也导出),归一化去标点空白后 ≥18 字才参与,含开引号的片段
  整段不参与 —— 切分器不认引号,它在引号内的句号上照样断句,台词会带着「她说:」这个前缀,
  只能按「含有引号」判。**同章重复 warn、跨章重复 info**,一句在 ≥3 章重复只报一条,
  落在第二处上以便 `--from/--to` 筛到。warn 只给这一处是有条件的:同章整句重复几乎只能是粘贴或模型回声,
  改一行就完事;跨章的不给 warn,因为「回声式复沓」是正当写法。
- **R27 `evidence-mismatch`**(书级):伏笔登记的 `setup.evidence` 在它标的那一章正文里字面找不到。
  找不到再扫全书 —— 在别的章找到 → 章标错了,证据把作者送到那一章;全书都没有 → 多半被后来的改写冲掉了。
  四类情形不查:依据不足 8 字、那一章还没写正文、章 id 不存在(那是 R15 的活)、登记已作废。
  `payoff.evidence` 不回查:回收依据指向的是将来那一章,正文没写是合法的。
- **R28 `world-destroyed-after`**(书级):`world[].lifecycle["destroyed-in"]` 由 `nw-changes` 的
  `world.destroy` 算子写入,导出导入一路带着走,**此前没有任何规则读它** —— 记了不查等于没记。
  取本名与 `keys` 里 ≥2 字的称呼,在销毁章之后的正文字面检索,一条设定只在最早撞见的那一章报一次,
  证据带 offset。`lifecycle["revealed-in"]` 不查:它没有任何生产者,而且世界条目的名字天然早于正式解释出现,

## M. 世界书递归触发 + 声明纠偏(已落地 —— 拆掉唯一一处「文档说 true、代码不做」)

审计 B 那条遗留不是在催功能,是在报一处不诚实:`bible/world/_index.json` 里写着
`recursive_scanning: true`、`scan_depth: 6`、`token_budget: 1400`,而 `loreTrigger` 三个字段一个都不读,
只做单层扫描;两个导出点各自手抄一份字面量,谁也没核对过。这次两边一起收口:**把功能做出来,
并让那三个值只能从引擎的常量算出来**。

- **级联的语义是「已经决定要给作者的设定,把它的同乡带进来」**:第 1 层扫正文,第 2 层只扫**已注入**
  那几条的正文。不是「把全库关键词再过一遍」—— 那只是每层都重扫同一个窗口,多烧一遍算力而已。
  被额度裁掉的条目不许当二跳来源:它的内容模型根本没看到,拿它带同乡会凭空多出设定。
- **两层封顶**(`NWStory.LORE_RECURSION`)。再深就会顺着「A 里有 B、B 里有 C」把整本世界书拖进 prompt。
  上限只有循环条件里那一处闸门;曾有的第二道 `if (round === maxRounds) break` 已删 —— 同一道闸门写两遍,
  删掉任一处都不改行为,测试区分不了,那就是一道假防线(K/L 两批的教训这次直接用上了)。
- **层数先于 priority**:额度跨层共享、前层先占。第 1 层命中的设定不许被第 2 层带出来的同乡挤掉 ——
  正文里点了名的那条离题更近。
- **防环靠 `consumed`**:本层命中过的(注入或被裁)退出后续层,没命中的留着 —— 下一层扫的是别的文本,
  它可能在那一层才被带出来。设定互相引用(a 提 b、b 提 a)不死循环、也不同一条注入两遍。
- **声明只有一个出处**:`loreIndexConfig()` 算出那三个字段,Web 导出(`project.js`)与 CLI 存盘
  (`scripts/lib/book.mjs`)各自展开它,两处都不许再出现字面量。字段名沿用 Character Card V2,
  取值按本引擎的语义:织文没有「聊天条数」可扫,`scan_depth` 记的是**扫几层**,
  `token_budget` 是字节额度 4096 换算成 token(汉字 3 字节 ≈ 1 token)。
  **方向是单向的** —— 这份文件声明引擎行为,不是本书的开关:`readIndex` 跳过 `_` 前缀,手改不改行为,
  下次导出会被重写(这是刻意的,见「没做」)。
- **`--lore` 要说得清来源**:人读那份给每条标「第 N 层,由「X」的设定带出」,JSON 给 `round`/`via`。
  递归最容易变成「这条哪来的」,不交代来源的召回没法信任。

## Q. 文风基准可注入(已落地 2026-09-30 —— 把「这一章像不像这本书」量成四个数,并且让作者说了算)

前十六批问的都是「这里错了没有」。文体这一类答不了这个问题:某一章口气变了,既不是对也不是错,
它只支持一句诚实的回答 —— **差在哪一格、差多少**。竞品那条方向(作者挑几段样例喂进 prompt 让模型模仿)
只做了前半件事:样例段是隐含信号,模型学到什么、下一章离题多远,无人能查。
于是这一批把两头接在**同一个函数**上:同一份指纹既写进 prompt(「你的基准是句均 17.3 字」),
又被 R32 拿来逐章回查,界面那一行与 CLI 也念它 —— 不会出现「prompt 里承诺的基准,检查器按另一套口径查」。

### 判据(只有一处:`src/core/stylefit.js`,v1.0.0)

| 格 | 怎么算 | 越界门槛 | 为什么是这个算法这个数 |
|---|---|---|---|
| 句均字数 `sentAvg` | 句总字数 ÷ 句数 | 相对偏离 >30% | 本底因人而异(短句流 12 字、长句流 40 字),绝对差不通用:12→16 比 40→44 严重得多 |
| 对话占比 `dialogue` | 对话字数 ÷ 总字数(取自 `NWTension.stats`) | >12 **个百分点** | 占比接近 0 时相对差会爆炸(1%→4% 就是 +300%,没人管这叫漂移) |
| 段均句数 `paraSent` | 句数 ÷ 段数 | 相对偏离 >40% | 切段习惯是笔法的一半,它和句均是两件事 |
| 禁词密度 `cliche` | 命中处数 ÷ 千字 | 绝对差 >1.5 处/千字 | 与 `NWStylePack.verdict` 的 info 档同值,那边「千字 1.5 处」已有出处 |

三条口径比表格本身重要:
- **计数先相加再相除**:`fingerprint()` 把池里每章的原始计数加起来才除。先平均各章比值,会让一章 200 字
  与一章 6000 字同权,那就不叫「这本书的笔法」了。
- **没有总分**。四格各说各话,作者对每一格都有处置权;合成一个分数就是把判断权交给统计。
- **「够不够长」只有一份判据**:`qualifies(body) = NWText.countWords(body) >= MIN_BODY(600)`,标点不计。
  指纹入口、界面画不画得动勾、`NWContext` 选样例、R32 与 CLI 问的都是它。

刻意不做:语义相似度、文笔高低、任何评级。`keys` 子命令里 `notMeasured` 那一格就是把这句写进机器输出。

### R32 `style-drift` 的误报控制(恒 info,置信度 0.6)

- **基准只认 `book.styleAnchor.chapterIds`,作者没勾过就整条闭嘴**(0 条诊断)。
  「那就就近取两章当标准」是这轮里被否掉的第一个念头:长篇里就近取的恰好是漂得最远的那两章,
  拿它当基准等于把漂移写成合格。没勾过时界面那一行、CLI 的报告都改说「按就近取已写章节挑样例」,
  并且明说 R32 在这种情况下一条不报 —— 不许两种情况都叫「基准」。
- **两格以上同时越界才报**:一格往往是这一章本来就是动作场面或独白,不是笔法变了。
- 基准章自己不评;带 `flashback/dream/quoted/offscreen` 标记的章不评(豁免名单从 `rules.js` 导出成
  `EXEMPT_FLAGS`,CLI 抄的是同一份);正文不足 600 字的章不评。
- 话术必须带实测值与方向:`句均字数 17.3 字→44.0 字（升 154%）`。只说「有漂移」等于没说。
- `evidence.basis` 是**有顺序的四件事**:勾了哪几章 / 基准几章几字 / 本章几字 / 越了几格与门槛各是多少。
  两章的基准本来比二十章的抖,全靠中间那两行说话 —— 少一行作者就少一个判断依据。
- 恒 info、永不拦生成。文体本来就是作者说了算的那件事,规则只负责把数字摆出来。

### 注入那一路(`src/core/context.js`)

- `stylePool()` 三态:`anchor`(勾过且合格)/ `auto`(没勾,取目标章之前最近的合格章)/
  `anchor-lost`(勾过但那些章正文都不够长,已退回 auto)。三态都得说得出名字。
- 一次最多 `STYLE_MAX = 2` 章;节选从 400 字起,超预算先**丢较远的那一章**,收到只剩一章还超就按 −40 缩节选,
  缩到 `STYLE_MIN_CHARS = 120` 仍超就如实带着超预算走 —— 压成碎片比超预算更没用。
- **先收样、再拿在场的这两章算指纹**,顺序不能反过来:反过来会出现「样例只剩一章、那一行却说 2 章 / 1746 字」。
  指纹行自己也要占预算,所以先扣 `FIT_LINE_RESERVE = 300` 字节再收样。
- 「风格样例」那一节带 `prose: true`,`renderPrompt` 把它提到所有约束之后 ——
  **动笔前最后读到的必须是正文语态的文字**,不是一叠禁令。
- `DEFAULTS.styleBytes` 1600→3000(两章 400 字节选加那一行放不下),而且这一批才**真的被读**。

### styleAnchor 过桥四处

`story.js` 的 `buildCtx`(界面与生成)与 `fromBook`(导入建档)、`project.js` 的导出与白名单、
`schemas/story-bible.v1.json`(object,`additionalProperties:false`,**不可 null**)。
「取消基准」的两种语义是分开的:CLI `--clear` **删掉这个键**(留 null 等于给这本书白添一条 schema error),
界面取消全部勾选写 `{chapterIds: []}` —— 两条路都落到「R32 一条不报」,但盘上形状不同。

### 界面(侧栏「文体规则」页)

按章号排的勾选清单;不够 600 字的那一章画成 disabled 并写明「正文太短,进不了指纹」。
那一行四个数用的就是 `NWStyleFit.fingerprint` + `lines`(界面上不另立口径),**跟着勾态当场重算**,按保存才落库;
「先只勾最早那一章」给一本没有基准的书一个起手。读取器只按 `checked` 收、不按 `disabled` 再滤一道:
正文后来变短的章仍带着作者原来的勾,滤掉等于一次保存就把他选过的基准抹掉。

### CLI `scripts/nw-style.mjs`

`fit`(缺省)/ `keys` / `anchor --set|--clear`,退出码只有 **0 · 2 用法或章 id 不在书里 · 5 读盘错**;
**偏离永不阻断**(真要门禁去跑 `nw-continuity`,而它那条也恒 info)。
子命令必须打头:`nw-style.mjs anchor <bookDir> --set ch-001,ch-002`。
JSON 形状:`baseline{source,declared,chapters,fingerprint}`、`injected{source,fitLine,chapters}`、
逐章 `role ∈ baseline|chapter|exempt|too-short`、`minBodyWords`(从包里现取,不是 CLI 自己写的数)。

### 顺手挖出来修掉的两处(都不是本轮计划,是接线时撞上的)

- **「600 字」这个门槛一直在按字符数判。** 旧代码是 `(c.body||'').trim().length >= STYLE_MIN_BODY`,
  而界面写着「正文 ≥600 字」、规则话术写着「正文不足 600 字」—— 标点也计进长度,于是作者会看见
  「480 字却能勾」:他眼前数的字数与他听见的门槛是两个数,而那一章根本进不了指纹。
  收口成 `qualifies()` 一份(按 `NWText.countWords`),四处调用点都不许再自己比 `body.length`;
  守卫盯的是 `qualifies` 函数体里必须是 `T.countWords(s) ... >= MIN_BODY`,且不许残留 `trim().length >= MIN_BODY`。
- **`styleBytes` 是死配置。** `DEFAULTS` 里写着 1600、注释还写着「opts.style 开启后才参与」,
  但全仓库没有一处读它 —— 旧的 `pickStyleExemplars(chapters, current)` 只接两个参数,注入量根本不按预算收。
  现在它是那条软上限的出处,默认值跟着收到 3000。

**六处「改了没人管」里有 5 处是已知冗余,留着并说清为什么**(它们不是行为分支,是把口径写在人眼前):
- R32 的 `if (!ids.length) return [];` —— 删了照样 0 条:`base` 是按 ids 筛出来的,空 ids → 空基准 →

- CLI 里 `basis = pool.source === 'anchor' ? pool.list : input.chapters` —— 两个分支都喂同一个 `fingerprint()`,

### 没做

- **库里已有的书在界面上看不到逐章指纹**:面板只画基准那一行。要知道「哪几章离基准远」,
  要么跑机检、要么开 CLI —— 塞进连续性页是另一处交互,还没定形。
- **基准不做推荐**:不告诉作者「哪两章彼此最像,勾这两章」。要做得先定义「像」是几格之内,那又是一个判据。
- 未知选项不拒绝:`fit --bogus`、`keys --bogus` 都退 0(该退 2);子命令也必须打头,
  写成 `nw-style.mjs <bookDir> anchor --set …` 会被当成一次普通 fit 报告,同样不报错。
- `book.json` 合法但缺字段时 `fit` 退 0(只有语法坏掉才退 5)—— 它不是校验器,那一职分在 schema 规则手里。
- 四个数只有均值:不含视角/人称,不含句长分布的方差。一句话流与长短交替流可能同为「句均 17.3 字」。
- 指纹与偏离**不入库、不留台账**(不像 `prose.json` 那样记「查过没查过」):留在盘上的只有
  `book.styleAnchor` 那几格,「这一章上个月偏离多少」没人记得。
- 注入的样例仍是「最近的合格章」,不按与目标章情节的相关度挑。
- R32 只比单章与基准,不比相邻章之间:渐进的漂移要累计好几章才撞得上门槛,中途每一章看着都「只越一格」。

## R. 状态矩阵范围收敛(已落地 2026-09-30 —— 一百八十章的书不再画一张拉不到头的长表)

### 这一批只管一件事:这一页画哪几章

矩阵是 角色 × 章 的二维表,章数是唯一会自己长起来的轴。写到 180 章就是 180 列,而它住在侧栏
那块 300px(`--sidebar-width`,实测可视 291px)的面板里。以前靠横向滚动硬扛,滚到第 60 列
连角色名都找不着。

**只裁视图,不裁数据**:库里那一格还在、点得到,R1/R2 照查,关掉窗口不等于状态丢了。
表下那句「翻到别页去点格子也一样改的是那一章的记录 —— 窗口只裁视图,不裁数据」就是这条不变量的人话版本。

### 判据(只有一处:`src/core/statescope.js`,v1.0.0)

- **`WINDOW_SIZE = 40`** 收的是 DOM 规模(20 个角色 × 40 章 = 800 个 td;180 章全画是 3600 个 td
  外加 3600 次 `byKey` 查询),**不是「一眼看得完」** —— 实测 40 列把 table 撑到 2279px,
  横向仍要滚 7.9 个身位,所以这话不敢在注释里说。
- **`ordered()`**:列序 = 阅读序。库里回什么顺序都不算,这里按 `order` 排一次,只此一处。
- **`normSize()`**:0、负数、NaN 一律退回默认那一页,而不是画出一列或空表。
- **`pageCount(total,size)`**:`max(1, ceil(...))`。total=0 也算一页,否则翻页条上写「第 0/0 页」。
- **`windowOf(chapters, size, back)`** → `{page,pages,visible,first,last,hidden,truncated,canBack,canForward}`。
  越界一律夹到最后一页而不是给一个空窗口 —— 「翻过头了所以整张表空着」是让用户以为数据没了,比多画两列糟。
  `start` 那道 `max(0, end - n)` 不能少:最早那页不满 40 章时会切到负下标。
- **`needsScopeBar(win)` = `win.total > WINDOW_SIZE`**:判的是「这本书比默认窗口长」,
  **不是「当前这一窗画完了没」**。按后者判会漏掉全书模式本身(那一状态下 truncated=false、pages=1),
  于是整条消失、切换钮跟着没了,作者从全书回不到分页 —— 这一条是浏览器真点才撞出来的。
- **`spanText(win)`** 说「第 141–180 章」,用 `order` 的实际值:删过章、章号断过也不谎报列数。
- **`lines(win, counts)`** 三件事必须齐:画的是哪几章、这一页之外还剩几章、
  「已记录 N 格」是这一页的还是全书的。少了最后一句,作者会把这一页的格数当成全书记了多少;
  两数相等时合说一个数,不写「这一页 40 格 · 全书 40 格」这种自问自答。
- `back` 是「往前翻第几页」(0=最近),而界面显示 `pages - back`(最老那页显示成第 5／5 页)。
  两处之间只隔着这一次减法,别再往下加。

## S. 卷级滚动压缩(已落地 2026-10-01 —— 前情摘要不再跟着章数线性变长)

### 这一批管的是「更早那一段到底怎么说」

三级衰减把最近 12 章逐章说、再往前 24 章只列章名,可**超出这两级往前的部分只剩一句「更早 N 章没提」**。
180 章的书里第 1–140 章对模型等于不存在:主角在第 3 章受的伤、第 12 章得的铜印,续写时一概看不见。
卷级压缩给这一段一个说法 —— 作者自己画区间(起始章—结束章)、自己写一行 120 字以内的摘要,
上下文里那一整段就压成一行。

**这一批不自动写摘要**。摘要是作者对「这一卷发生了什么」的说法,机器替写会把「作者以为的主线」
换成「词频算出来的主线」;那是另一件事,这一批没假装做了。

### 判据(只有一处:`src/core/volumes.js`,v1.0.0)

三条不许商量的:

- **没写摘要的卷不盖章**(`empty` 桶)。它框住的章退回原来的层级,缺口那句单独报这一卷。
- **盖到目标章及其之后的卷不注入**(`deferred`)。那半卷剧情还没发生,写了就是剧透。
- **起止章在书里读不出来就判坏**(`bad`),`missing`(边界章被删)与 `reversed`(填反)分开说,
  **绝不按 `order` 猜区间** —— 猜出来的可能盖住完全不同的几十章。

分层与覆盖的算法也在这里,不在 `context.js`:`RECAP_FINE=12` / `RECAP_MID=24` / `VOL_WINDOW=12` /
`VOL_LINE_CHARS=120` 四个数加一份 `recapPlan()` 口径。`context.js` 只留 `RECAP_ITEMS`/`RECAP_MID` 两个别名,
`rules.js`(R33)与侧栏面板读的都是同一份 —— 两处窗口各长各的是这批最容易犯的错,
所以守卫里钉着「面板的分层只问 volumes/context」。

`recapPlan` 返回的每个桶都要能说出口:`fine`(逐章)、`titles`(章名层)、`volumes`(真注入的那几卷)、
`folded`(卷数超 `VOL_WINDOW` 时最老的折成一句「更早 N 卷、约 M 章已折」)、
`partial`(压在细窗口那一段上,说的是重复不是缺口)、`empty` / `bad` / `deferred` / `overlaps`,再加 `counts`。
`covered` 是**集合**:两卷重叠的那几章只算一遍,而 `overlaps` 存在的理由正是「压掉 30 章」这句话里有水分。

## V. 工作流预设(已落地 2026-10-01 —— 作者调顺的那三格头一回能从一本书走到另一本书)

### 这一批管的是「盘上一直没有地方放那几格」

roadmap 从 P1-2 起就写着「工作流 / 模板分享」,而它从来没有载体:篇幅档、全篇字数目标、
去 AI 味八组的开关散在建书向导、设置页与「文体规则」页三处,开第二本书得从头再调一遍,
而且**调完对不对没人能核对** —— 没有一份文件能回答「这套设置搬到另一本书会改哪几格」。
这一批补的是那个载体,不是一个新的界面。

### 判据(只有一处:`src/core/workflow.js`,WORKFLOW_VERSION 1.0.0)

- **`FIELDS` 那三格是唯一清单**:写预设、读预设、画 diff、schema、CLI 都问它要。抄第二份
  就会少一格,而少的那一格谁都不报错 —— 这是本仓反复犯的那一种。
- **`normalize` 把外来文件分成三堆,每堆都要说得出口**:`errors`(kind / version 不对、顶层不是对象、
  一格设置都没有、**认不出的键**)、`bad`(值不合理的那一格,点名原因)、`fields`(过了闸的格)。
  **认不出的键整份拒收**,不是「剩下的照用」:一份带我们没见过的高阶设置的文件用半份下去,
  分享者以为那套已落地,接收者看不出没落地的那部分。
- **`TARGET_MIN = 1000` 不是这儿首创** —— 它写在 `schemas/story-bible.v1.json` 的
  `book.target_words.minimum` 里,预设搬的正是那一格。两处不同就是「导得出去、进不来」,
  守卫拿两份 schema 对着这个数核。
- **`LONG_NO_TARGET` 那一句只有一个出处**:过闸要说它(长篇配目标是坏搭配),逐格 diff 也要说它
  (长篇收到只带目标的预设,那一格落不下)。两处各写一句,就会一处拦、一处照写。
- **`NOT_SHARED` 各带一句为什么**:`styleAnchor` 记的是这本书里若干章的身份证,换一本书那些 id
  就指不到东西 —— 那是身份,不是设置;书名 / 类型 / 简介是「这一本是什么书」,不是怎么写书。
  所以**换书后基准章要重新勾**,这不是遗漏。
- 三格之外刻意不进预设:预设带 prompt 文本 = 界面上填不出、导出不往返的东西不算设置。

### 一行的三种落法(这一批真正的难点)

`diffFields` 每行带 `changed / blocked / clears`,三种写法库的量不一样:

- **`changed`** —— 画箭头,写 `fields[key]`。
- **`blocked`** —— 那一格在这本书里落不下(长篇 + 只带字数目标的预设)。不画箭头、一个字都不写,
  原因照 core 那一句念出来。**也不许报成「这一本已经就是这套工作流」**:落不下不等于已经对了。
- **`clears`** —— 反方向。预设自己把篇幅档换成长篇时,库行里那个 `target_words` 得如实清掉(写 `null`)。
  判据看的是**应用之后**的篇幅档,拿换之前的档拦就等于把整套短篇工作流挡在门外。而 `pack` 会替长篇
  把那一格藏起来 —— 那个数还躺在库行里:进度条不画、面板说「(这一格没设)」,**评分卡照样按它算分**。
  所以这里读的是库行原值,不是 `pack` 的产物。导出那一路 `pick()` 连 `undefined` 带 `null` 一起丢
  (见 `src/core/project.js`),出去的文件里根本没有这一格,所以那个 `null` 撞不上 schema 那道非空上限。
- **预设没带 `format` 时一格都不许多清**:顺手抹掉作者自己定的目标,破的就是「应用只改它带来的那几格」。

## W. 单章字数收成一处(已落地 2026-10-01 —— 模型照 prompt 的上限写满,回头机检报它超上限)

### 病灶:同一个数在三个地方各说一遍

「一章该写多长」这件事,仓库里同时存在四份互不知情的说法:

最坏的那一条不是「数字不一致」这么温和:模型照 prompt 的 5000 字写满 → R35 之前的机检无话,

### 判据(只有一处:`src/core/tension.js`)

- **`CHAPTER_RANGE = { long: [1200, 4000], short: [400, null] }`** 是这一串数的唯一出处,

- **`isShort(book)` 是唯一换挡**:只认 `book.format === 'short'`,认不出一律按长篇。

- **`rangeLabel(key)` 是唯一话术**:对人怎么说这一档(「1200-4000 字」/「400 字起,上不封顶」)

### 短篇为什么不封顶(`null` 那一条的理由,它本身就是这一批的一半)

同一份 `llm.js` 里的短篇向导自己就写着 `SHORT_TIERS`(微型 3k-6k 字 / 1-2 章)与
`SHORT_PLATFORMS`(公众号 6000、番茄 20000、盐选 50000)。5 万字摊 6 章,单章最坏 8300 字。
给短篇安一个比这小的上限,等于机器天天报一个作者照着本软件界面选出来的计划 ——
那种诊断不是信息,是噪声。长篇有上限是因为长篇的章数由作者自己拆,短篇的「章」是一节,
长度跟着总字数与投放平台走。

### 新规则 R35 `chapter-length`(恒 info)

- 判什么:一章 `countWords(body)` 落在本书那一档区间之外,低报「差多少字」,高报「溢出多少字」。
- `evidence.basis` 三行:计数、本书按哪一档那一档是多少、字符数(说明它**不参与**判定)。
- 不评:正文空着的章(还没开写不是缺陷)、带 flashback/dream/quoted/offscreen 的章(那几类本来就短);
  `montage` 不豁免。
- 计数一律 `NWText.countWords`,不是 `body.length`:1150 字的正文带 420 个标点字符是 1570 字符,
  按字符数它已经"达标"了 —— 而对话密的那一类章正好最容易撞这个误报。
- **不查总字数**:规划字数 ÷ 章纲数是评分卡 length 维的事(动笔前),R35 看的是成稿(写完后)。
- **恒 info 是接通的必要条件**:`src/core/selfcheck.js` 的 `actionable()` 只收 `error`/`warn`,
  抬成 warn 等于让自修补写去凑字数,烧的是用户的 API 额度。

### 行为变化(三条,都是改口不是加功能)

1. prompt 那句承诺:长篇 3000-5000 → **1200-4000**;短篇 → 「400 字以上,这一档不封顶」。
2. R17 的评审门槛:私有 300/800 → `QUOTAS.*.minBody`(同一份);计数字径 `body.length` → `countWords`。
   后果是标点密的章**不再**被抬进钩子评审(原先 350 字符 / 280 字的章会被评,现在不评)。
3. 评分卡短篇那一档不再有 4000 的上限:「微型 6k 字 1 章」原本被判成坏计划(score 1-2),
   现在 score 3。

## Y. 「这一档有没有字数目标」收成一处(已落地 2026-10-01 —— 建档宽、打包严,同一个数在界面是「没设」而评分卡按它给分)

X 收掉了「这本书算哪一档」,但那一档还牵着下一句:**只有短篇有「全篇字数目标」这一格**。
这一句当时写在三处,而三处不是同一句:`db.js:200` 建档用 truthy(`format === 'short' && targetWords`),
`workflow.js` 打包与逐格 diff 用 `Number.isInteger(...) && >= TARGET_MIN`,`app.js` 进度条与
`pitch.js` 直接拿原值算。下限那一个数当时住在两份 schema 的 `target_words.minimum` 与
`workflow.js` 各一份。

### 病灶:一宽一严,同一个数两张嘴

- **短篇 + `target_words: 500`** —— 建档照存(truthy 就过),进度条画出一条 0%,评分卡按 500 字评
  篇幅匹配,而 `pack` 说这本书根本没设目标;导出去的 `book.json` 带着 500,**过不了自己那份 schema**
  (`minimum: 1000`)。作者界面里看得见一个数,而这份存档在别人的机器上算违规。
- **长篇 + 库里的遗留数 8000**(旧版建过短篇、`update`/`putRow`/导入留下的)—— 进度条不画、
  工作流面板说「这一格没设」、`pack` 不带它,而评分卡的 `length` 维**按 8000 给分**。
  `workflow.js` 里那句现成的注释早就写了这件事会发生在哪一头,只是没人去改另一头。

### 判据(还是 `src/core/tension.js` 那一家,添两句半)

- **`TARGET_MIN = 1000`** —— 下限唯一的数。出处仍是两份 schema 的 `target_words.minimum`
  (守卫拿那两份对着它核,谁改这个数就要连 schema 与夹具一起想),`NWWorkflow.TARGET_MIN` 是指向它的别名
  (与 W 的 `LENGTH_RANGE`、X 的 `FORMATS` 同一做法)。
- **`targetValue(raw)`** —— 「这个数本身算不算一个目标」,**不问哪一档**。字符串数字收回整数,
  小数、负数、`true`、`{}`、`['8000']`、`Date` 一律算没设(后两条是 `typeof` 那道闸的工作而不是下限的:
  `Number(['8000'])` 是 8000,`Number(new Date())` 是 1.7 万亿,只比下限它们都能混进来)。
  用它的两处都必须与档无关:预设过闸判的是**这份文件写的数**,逐格 diff 判的是**库里那个数还躺着没有**
  —— V 那条「遗留的长篇库行:应用只带长篇的预设时那一格一并清走」靠的就是能在长篇行里看见那个数。
- **`targetOf(book)`** —— 「这一档有没有那一格,那个数是多少」:先问档(长篇/认不出 → 没有这一格),
  再问数。库行的 `target_words` 与 `ctx.book` 的 `targetWords` 两种形状都问它,`target_words` 优先。

改口之后 core 那两句一共被点名八处,守卫逐处数:问「这一档有没有那一格」的六处 —— `db.js` 建档、
`story.js` `fromBook`(导入建档)、`story.js` `buildCtx`(装配 ctx)、`app.js` 侧栏进度条、
`workflow.js` `pack`、`pitch.js` 的 `ctx` 那一头(那一路见下一节);
问「这个数本身算不算一个目标」的两处 —— `workflow.js` 的过闸与 `diffFields` 的 `leftover`。

### 刻意没并成一句的那一路

`pitch.js` 的两种入参在这条线上是**分开的**:`ctx`(已经写成的书)读库里那一格,走 `targetOf`;
`concept`(向导与 CLI 当场填的)读「作者打算写多少」,那是规划 —— 长篇的向导平台档与 `--words 200000`
都给得出这个数,它从来不是库里那一格。并成一句只有两种坏结果:把长篇的规划判死,
或者把库里的遗留数当目标用。守卫把这一句 `isCtx ? … : …` 整行钉住,绕过它要在守卫里说清是哪一路。

### 行为变化(四处可见,其余都是改口)

1. **建档**:短篇配一个低于下限或不是整数的目标,以前照存,现在留空。那本来就是一份过不了自己
   schema 的存档;界面上没有任何一处能填出这种数(短篇向导给的是平台档 6k / 2 万 / 5 万,长篇向导传 `null`)。
2. **导入建档与导出**:长篇那本书的目录里带着 `target_words` → 不落库、也不带出去。
   界面那一格在长篇这一档根本不存在,带出去就是让别人的机器收到「面板说没设、评分卡却按它算分」的存档。
3. **选题评分卡**:长篇书那个遗留目标不再参与 `length` 维,如实给「没填目标字数」—— 那句建议本来就写着
   「长篇自己定一个总字数」,以前分数与建议互相不知道对方存在。
4. **侧栏进度条**:不合法的遗留数不再画出一条谁也算不清的进度条(`pack` 的人读输出同理)。

## C. 模型输出的残缺与出界的数(已落地 2026-10-01 —— TypeError 不如一句人话,「下限」旁边补上「上限」)

C 级工程约定清单上的两条:`parseConceptJSON` 缺 `characters` 裸抛、字数校验缺硬上限。

### 病灶

- **缺人物裸抛**:`parseConceptJSON` 的闸只验书名与章节,模型返回的梗概缺 `characters` 时闸放行,
  代码在 `j.characters.slice` 上抛 `TypeError: Cannot read properties of undefined` ——
  modal 的保存处理器是 async 的,异常变成 unhandled rejection 被吞掉,作者看到的是「点保存毫无反应」;
  `"characters":[null]` 同理,死在 `.name` 上,换了个门而已。
- **只有下限**:`TARGET_MIN = 1000` 对着 schema 的 `target_words.minimum` 核,而两份 schema 里
  根本没有 `maximum` —— 一个 1.7 万亿的目标照样过闸、进库,进度条分母是它,

  零人物的书 R29-R31(出场回查三连)全部失效,建档就是带病。
- **tension.js**:`TARGET_MAX = 100000` 与 `TARGET_MIN` 并排,`targetValue` 上下限一起问。

  长篇没有这一格(建档留空、换档清走),评分卡里长篇的规划数也不打这里过

## E. 字数目标在界面上改得动(已落地 2026-10-02 —— Y 归一之后这格只剩一个说法,那就给它一个入口)

C 批把它列为「界面加『字数目标』编辑入口」,Y 与 Z 两批的遗留里是同一条:这一格只有**建档与预设应用**
两个写入处。作者手上是一本短篇,想把目标从 8000 改成 12000,路径却是「重开一本书」或
「找一份恰好写着 12000 的预设」。归一做完之后这一格在 core 里只有一句话,所以加入口不需要造第二份判据 ——
需要的是把界面上那个输入框**当成一份只带这一格的预设**递进已有的那道闸。

### 判据(`src/core/workflow.js`,还是那一家)

- **`TARGET_FIELD = FIELDS[1]`**:那一格的名字从可分享清单里取,界面不许再打 `'target_words'`
  这个字面量(guards 那份禁用清单),而 `TARGET_FIELD` 与 `FIELDS[1]` 与字面量三方对齐由一条测试钉着
  —— 别名漂到别的键上,界面上填的字数就交进了别的格子。
- **`leftoverTarget(book)`**:「库里到底还躺着那个数没有」,只问原值不问档(问档是 `Tension.targetOf` 的活)。
  `diffFields` 拿它判长篇要不要清走,界面那句「还躺着 9000 字」也念它。收成一处是因为 V 批第七起:
  视图把格子藏起来,数还在库里而界面一个字都不提。
- **空着的说法**:`''` 与 `'   '` 和 `8000.5`、出界同一个 `bad`,理由多半句「空着不算撤掉这一格」。
  这一路只能改不能撤,闸门如实说它不收这一格,不静默当成「清掉」。这句话只许出现在 core 的拒绝理由里,
  界面 hint 不许抄(抄了就有第二份说法,改一处忘一处)。

### 行为变化

- 侧栏「工作流」页短篇多一个输入框:`value` 是 core 打包出来的当前值,`min`/`max`/placeholder 全从常量念;
  长篇不画框,只给 `LONG_NO_TARGET` 那一句,库里若还躺着一个数,第二行把它说出口。
- 点「按这个数改」= 造一份只带这一格的预设 → `normalize` 过闸 → 同一张逐格 diff 确认框 → `patchOf` 写库。
  V 批那三条语义(blocked / clears / 「一格都没动」)一行不重写就全继承:改到与库里一样的数,
  框里画「(不变)」,写库那一格数 0。
- 出界与留空走拒绝框、理由逐条念;界面自己既不比上下限,也不 `novels.update`。

### 测试(696 → 703,规则 31 条不变)

- **workflow**:leftoverTarget 不问档;面板念的遗留数与 `diffFields` 判的是同一个数;字符串收回到整数、
  出界与空串都拒、空串那句「空着不算撤掉」;改到相同数补丁是空的;`TARGET_FIELD` 三方对齐。
- **guards**:假 DOM 下短篇画得出框(value/min/max 由常量填,不许出现字面量数字),
  长篇不画框且两句各占一行,**面板里真的有人调 `workflowTargetEditor`**;那一路处理器必须过闸、
  进确认框、不自己写库,且交进闸门的是输入框原值(不许兜一个默认数)。
- 两条既有计数守卫重新定标(不是回退代码,是守卫自己要求「多一处少一处先说清是哪一路」):
  app.js 的 `NWTension.isShort(` 4→5、`NWTension.formatLabel(` 3→4,各多工作流页这一路。

### 反验(改值 10 处 + 删行 4 处)

全部红在预期名下,**但头一遍有一处是绿的**:删掉面板里 `${workflowTargetEditor(own)}` 那个调用点,
703 项照过 —— 假 DOM 那条是自己 `new Function` 把函数抠出来直接调的,谁都没看「面板到底画不画它」。
补了 `assert.match(panel, /\$\{workflowTargetEditor\(own\)\}/)` 再跑才红。同一类形状的第二例提前防住:
处理器里给 `const filled` 兜一个默认数(`|| '5000'`),那句「空着不算撤掉」就成了假话,
所以那条断言钉的是原值交闸。

### 真跑(CLI)

- `nw-workflow.mjs keys` 输出与 C 批一致(上下限那行人话照旧,退 0)。

  逐格对照三行全「(不变)」;`check` 一份只带 12000 的预设 → 退 0,「全篇字数目标:8000 字 → 12000 字(要改)」
  加「这份预设不带:篇幅档、去 AI 味规则包」;`check` 一份 200000 → 退 1,理由是那句上下限。

### 真跑(浏览器,5599 静态服务器,注销 SW 后走真实事件)

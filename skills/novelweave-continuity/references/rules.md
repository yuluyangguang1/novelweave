# 规则规格

实现只有一份：`src/core/rules.js`（浏览器与 Node 共用）。本文件解释**为什么这样判**
以及**误报是怎么控制的**。用 `nw-continuity.mjs explain --rule <代号>` 拿机器可读版本。

`rule-crashed` 是引擎内部异常自保护，出现即说明引擎有 bug，应反馈而不是照办。

## machine 规则

### R1 `dead-character-on-stage`（error）
**输入**：`characters[].status/died-in`、`chapters[].characters/flags`、正文。
**判定**：对 `status=deceased` 且章号大于 `died-in` 的每一章——
① 该章 frontmatter 的 `characters` 含此人 → error（作者亲口声明他出场）；
② 否则扫描正文，名字/别名出现点之后 30 字内命中动作词表 → error。
**误报控制**：
- 该章带 `flashback`/`dream`/`quoted`/`offscreen` 标记 → 完全跳过；
- 名字紧跟「的」（跳过标点与引号后）→ 视为领属提及（"明长老的说法"），不算行动；
- 出现点前 60 字含回忆标记词（当年/那时/生前/记忆里/幻影/识海…）→ 降为 `info`，
  而不是闭嘴不报，让作者自己决定要不要加 flag；
- `suppressions.json` 命中 `fingerprint` → 标 `suppressedBy`，仍保留在报告里。
**为什么动作词表这么长**：只判"名字出现"会把 90% 的正常提及报成矛盾，
那种检查器一周内就会被作者关掉。

### R2 `status-declared-contradiction`（error / missing 为 warn）
角色卡 `status`、`died-in`、分章状态快照三者任二者互斥即报。
`deceased` 但没有 `died-in` 单独成条（代号 `missing-died-in`），因为它会让 R1 全线静默——
不知道死亡章号，就无法判断"之后"的出场。

### R3 `promise-unpaid`（warn，翻倍阈值升 error）
`weight=major` 埋设后 ≥10 章未收报 warn，≥20 章升 error；`minor` 阈值为 25/50。
**不报的情况**：`weight=candidate`（脚本自动登记、作者尚未确认的，不该打扰作者）；
设了 `payoff.due` 的（交给 R3b，避免同一伏笔报两条）。每书最多输出 8 条，按紧迫度截断。

### R3b `promise-overdue`（error）
最新章号已超过 `payoff.due` 但状态不是 `paid-off`/`dropped`。

### R4 `payoff-before-setup`（error）
`payoff.chapter` 的号 ≤ `setup.chapter`；或状态已是 `planted`/`paid-off` 却没有登记埋设章。
后者是最隐蔽的一类：伏笔实际上从未被埋过，读者只会觉得"这事哪来的"。

### R7 `appearance-token-violation`（until 违规 error / since 之前 warn）
靠 `appearance.tokens[].{since,until}` 判定：
- `until` 之后正文仍出现该特征 → "断臂长回来了"，error；
- `since` 之前出现 → 特征提前存在，warn。
**误报控制**：出现点前 80 字含"想起/仿佛/好像/像从前"→ 降 `info`；
`allowIn` 白名单章跳过；token 少于 2 字不判；每个 token 最多报 3 条，不刷屏。
这个字段是我们加的，Character Card V2 与 story-skills 都没有——
它是把外貌连续性变成机器可判的唯一办法。

### R9 `unregistered-entity`（info，confidence 0.5）
候选抽取：「常见姓 + 1~2 字」与「2~4 字 + 称谓后缀（长老/宗主/仙子/公子/前辈…）」两式。
**误报控制**：姓氏式要过一道虚词闸 —— 候选里含「他/们/了/的/是/在…即弃」，因为「路他已」「经看了」
这类是普通词恰好从姓字开始；称谓式**不过滤**，那本身就带信息（林夫人、张道人都含「人」）。
三重闸之后才报：出现 ≥2 次、跨 ≥2 章、且不在 `lexicon.names`、角色本名与别名、
世界条目名与 `keys`、`allowlist` 之中。**聚合成一条**列出 top 15。
它的作用是养 lexicon，不是骂作者，所以永远是 info。
抽取器 `NWRules.entityCandidates` 与 `nw-io.mjs adopt` 共用一份 —— 建档时看得见的名字
和检查时报出来的名字必须是同一批。

### R6 `timeline-regression`（error；`implied` 只出 info）
按章序遍历带 `day` 的锚点，为每条 `thread` 维护至今的最大时间戳（`day + 时辰折算`），
后来的锚点时间戳更小即判**时间倒流**。
**误报控制**：
- 不同 `thread` 之间**永不比较** —— 多线并行是合法叙事，放一起比必然误报；
- 锚点所在章带 `flashback`/`dream`/`quoted`/`offscreen` 标记 → 跳过该锚点；
- `confidence: implied`（从"三天后"这类叙述推出来的）一律降 `info`：推断的时间不可靠，
  让它报错只会逼作者关掉检查器；
- 判出回退后**不回写最大值**，避免一个填错的锚点引发后续连锁误报。

时辰必须参与比较（黎明 < 晨 < 午 < 暮 < 夜 < 三更），否则「第 1 章夜里发生、
第 2 章写当天清晨」这种真回退会被漏掉。

### R14 `structure-invalid`（error，slug 重复与缺号为 warn）
章号非 ≥0 整数（`0` = 前置章，楔子/序）、重复、id 重复、slug 冲突、status 非枚举、章号有洞。
优先级最高：章序一乱，所有依赖 `number` 比较的规则都会产出假诊断。

### R15 `dangling-reference`（error）
扫描章 frontmatter 的 `characters/mentions/locations/pov/time_anchor`、角色卡的
`first/died-in`、伏笔登记表的 `setup/payoff/due/characters`。
断链必须显式报出，否则相关规则会**静默失效**——那比报错危险得多。

### R16 `derived-field-touched`（warn）
`x-words`、`_derived.words` 与重算值不符。说明有人手改了派生字段，或写完正文没重算。

### R17 `chapter-end-hook`（info，永不进退出码）
章末没有钩子信号：本章未新埋伏笔（`setup` 指向本章），且结尾 300 字内无问号/突转/留白类标记。
先过长度闸——长篇正文满 800 字、短篇满 300 字才参加判定，否则短章会被误报。
带 `flashback` 等豁免标记的章跳过。**钩子的质量机器判不了**，本条恒为 info，
只提示「这一章结尾可能平」，不代表写得不好。

### R18 `item-reappear`（info，书级，永不进退出码）
以状态矩阵为准：某条目在「持有物」里被记录 → 之后连续缺席 → 再往后又出现在持有物里。
要么中间章节忘了记，要么失去了又重新获得却没写。
**矩阵没记不等于物品不存在**，所以本条只提示补账或补情节，恒为 info。

### R19 `relation-contradiction`（warn，书级）
以 `relations.json` 的边为准，两件事一起判：
① **双向一致**：同一对角色（无序对）存在 `kind` 互不相同的边 → warn，
建议修正另一条，或给其中一条加 `until` 表示关系已随剧情变化。
② **称谓相符**：登记了 `address` 的边，若该章正文同时出现双方名字、
却不含登记的称谓而含其他强称谓词（哥哥/师父/大人/叔…）→ warn。
**误报控制**：
- 关系是作者登记的结构化事实，判定不经模型、不经词频统计，故属机器规则；
- 但称谓的设计空间大（口癖、反讽、关系转变期都可故意错称），所以判到只给
  `confidence 0.5` 的 warn 而非 error，且可按指纹豁免；
- 双方名字未同章在场、或正文已出现登记称谓 → 不报。
**没登记就没有这条**：`relations.edges` 为空时 R19 全线静默，
它不猜关系。AI 抽关系边（提案制）是补登记的入口，不是自动生效的前提。

### R20 `premature-reveal`（error / 铺垫起点内为 info / 无排期为 warn）
**输入**：信息差账本 `secrets[]` 的 `term`、`first_chapter`、`reveal_chapter`、`revealed_at`，加上各章正文。
**判定**：基线取 `revealed_at`（已经写出来的实际揭示章），没有则取 `reveal_chapter`（排期）。
在基线之前的章节正文里对 `term` 做字面检索，命中即 error，诊断落在那一章。
**误报控制**：
- 只认 `term` 的字面出现。它要求登记时填的是**读者在正文里看到的那个词**（"玄冰令"），
  不是事实的复述（"掌门害死林父的信物"）——后者永远匹配不到，规则会全线静默；
- 带 `flashback`/`dream`/`quoted`/`offscreen` 的章整章跳过：回忆与引文里出现旧信息是合法叙事；
- 登记了 `first_chapter`（允许开始铺垫的章）且命中章不早于它 → 降为 `info`，
  那是作者自己批过的提前露面，提醒确认而不是判错；
- `reveal_chapter` 指向不存在的章 → 跳过，那条错引由 R15 报，R20 不重复喊；
- 既没排期也没回填、但正文已出现 → 只报 warn 催登记，**不猜这是不是剧透**。
**为什么值得做成机器规则**：剧透是设定级事实的违反，判据是"登记过的揭示章"与"字面出现在哪一章"，
两条都是结构化数据比较，不需要模型理解语义。

### R21 `unresolved-secret`（warn，书级）
设了 `reveal_chapter`、`revealed_at` 仍为空，最新章号已经过去，而 `term` 在**全书正文里从未出现** → warn。
命中说明两件事之一：揭示那段根本没写，或者揭示时换了别的说法（登记的词与正文用词不符）。
哪种由作者判断，规则只负责指出"账上挂着、正文里没有"。
**不报的情况**：排期章就是最新章（还没到期）；已回填 `revealed_at`；正文里出现过（那是 R20 的范围，不重复报）；
`enabled=false` 或 `term` 为空。
和 R18/R19 一样，这条**以登记为前提**：账本空着它无话可说。

### R22 `ai-flavor`（warn / 密度只到一半为 info，正文不足 500 字不评）

全书唯一一条查文笔腔调的机器规则，判据全部是统计，不做主观评价。数据源是
`src/core/stylepack.js` 那份「去 AI 味」包（`lint` + `verdict`），与生成时写进写作要求的那份
清单**同源**——两边各写一份迟早会变成「prompt 里禁 A、规则里查 B」。

- **禁词密度**：8 个词组（心理直说 / 比喻引导词 / 眼神套路 / 抽象概括 / 转折套话 / 反问铺垫 /
  副词堆叠 / 段尾金句）。每千字 ≥3 处 warn，1.5～3 之间 info。
  「副词堆叠」按段落判（同段 ≥2 个程度副词才算一次），「段尾金句」只在段尾 24 字内匹配。
- **句式套路**：连续多句同一开头、连续三段无对话、二元对照句（不是 X，而是 Y）、
  三短句连击（连续三句都 ≤7 字）、破折号插入语（按千字密度）、「的」字堆叠（同一句叙述里
  5 个「的」，对话句不算）、一句到底不断句（60 字以上且句内无逗号顿号）。踩到 **两类及以上** 直接 warn。
- `evidence` 带 `per1000`、每类句式的 `count`、高频禁词和一段可回查的原文引证。
- **不报**：正文不足 500 字（一段闲笔不当成文风问题）；本书 `stylePack.enabled=false`；
  某个词组被作者在侧栏「文体规则」页勾掉。句式五条跟着整包走，不能单独关。

`confidence` 0.6（机器规则里"拿不准就降档"的同一套写法，与 R1/R3/R7 的软化分支一致）。
但它是 machine 诊断，`severity=warn` 就会进 `runSelfCheck` 的 actionable 集合：连续生成时本章
因此多走一轮自修改写。把它当提示用、不当门禁用——误报了在侧栏关掉那组，别拿它判定一章不通过。

### R23 `dialogue-ratio` / R24 `chapter-no-change` / R25 `same-hook-streak`（一律 info）

这三条是规则表里唯一的**正向**规则：R1–R22 查「不能错 / 别这么写」，这三条查
「该有而没有」——一章里有没有人开口、有没有改变任何一件事、结尾是不是又用了同一招。
统计判据全在 `src/core/tension.js`，与写之前进 prompt 的那段配额**同源**。

**三条恒为 `info`**，这是设计而不是偷懒：`warn` 会进 `runSelfCheck` 的 actionable 集合，
等于让模型为一凑配额去补对话、补伏笔 —— 那正是配额规则最坏的用法。它们也不进退出码。

- **R23** 数据源只有正文。对话字数按**成对**引号（`“”`/`「」`/`『』`）内的文字计，
  占比 = 对话字数 / 全章字数；另一路判据是最长纯叙述连段（按段落累计，遇到有人开口的段落归零）。
  长篇门槛：占比 < 8% 或连续 ≥800 字无台词，且整章 ≥1500 字；短篇 10% / 600 / 400。
  不评：`flashback`/`dream`/`quoted`/`offscreen` 标记章（`montage` **不**豁免，混剪章也该有人说话）。
  一处漏掉的后引号会让它后面的叙述被当成对话，误差方向是少报不是多报。
- **R24** 数据源只有账本，不碰正文质量：伏笔表的 `setup`/`payoff` 指向本章、
  状态矩阵里某实体相对它**上一次**记录的维度有实质差别（首次登记不算变化，那多半是补账）、
  信息差账本的 `reveal_chapter`/`revealed_at` 落在本章。四者皆无才算平章。
  全书一条登记都没有时整条规则不输出 —— 惩罚不记账的作者只会换来作者关检查器。
  连续两章都是平章时，后一条的 `message` 会明写「上一章同样如此」并换一条建议。
- **R25** 只认两类判据确凿的钩子：结尾 120 字内有问号 = `question`，命中突转词表 = `twist`，
  其余一律不分类（不猜「留白」）。同一类连续 ≥3 章才报，诊断落在这段的**首章**上，
  所以 `--from/--to` 能筛到它。换型或中间插一章平收尾即重新计数。

### R26 `repeated-sentence`（跨章 info / 同章 warn，书级）

查的是**逐字**重复，不是"这两段写得像"：句子取自 `NWStylePack.sentences`（与 R22、R23 同一把刀），
去掉标点与空白后 ≥18 字才参与比对。两种典型病灶——

- **同一章内原样出现两遍**：`warn`。到这一步几乎只能是粘贴残留或改写时没删掉旧句，
  自修补写一轮就能消掉，所以这一条是这批里唯一给 warn 的。默认门禁是 `--fail-on error`，不会因它红。
- **后面的章节一字不差又写了一遍**：`info`，诊断落在**后一章**上（`--from/--to` 才筛得到）。
  跨章不给 warn 是有意的：让模型"凑掉"一句复述，它可能顺手删掉真内容。
  同一句在 ≥3 章重复时只报一条，措辞按"像固定用语"写（系统提示语、人物口头禅都长这样）。

不报：含开引号的片段（切分器**不认引号** —— 它在引号内的句号上也断句，所以台词可能带着
「她说：」这个前缀，只能按"含有引号"判；复沓式台词机器分不开就别报）、带 `flashback`/`dream`/`quoted`/`offscreen`
标记的章整章不参与（回忆章本来就该重演旧场景）、短句与四字格。归一化只到"忽略标点空白"，
所以换标点不换字仍算重复——这正是改写时最容易漏的那种。

### R27 `evidence-mismatch`（info，书级）

伏笔登记里的「原文依据」是唯一能让人（和 R3/R3b）回到正文的锚点，正文一改写它就悄悄烂掉。
把 `setup.evidence` 归一化后在 `setup.chapter` 的正文里找；找不到再扫全书，分两种说法：
在别的章**找得到** → 内容没记错、章标错了，诊断指向那一章（点得到回去）；全书都没有 →
多半是改写时把这句删了，诊断指向登记的埋设章。

不查：依据不足 8 字（太短，找不到也不说明问题）、那一章还没写正文、`setup.chapter` 指向不存在的章
（那是 R15 的活）、`status: cancelled` 的登记。恒为 `info`——"凭记忆摘了一句"和"依据过期"
在正文里长得一模一样，机器分不出，就不替作者断定。

`payoff.evidence`（回填时记的那句）不在本条范围内：它的语义是"这里是回收处"，
不是"当初埋在哪"，混进来查会把大量正常回填报成问题。

### R28 `world-destroyed-after`（info，书级）

只读 `world[].lifecycle['destroyed-in']`。这个字段有两个写入处：`nw-changes.mjs` 的 `world.destroy`
算子，以及侧栏「世界设定」表单里的「在第几章被毁掉」——后者补上之前，这条事实上只有命令行用得上。
导出与三方合并一路带着走，**此前没有任何规则读它**——记了不查等于没记，这条就是把那半截接通。
取 `worldForms(条目)` = 本名 + `keys` + `secondary_keys` 里 ≥2 字的称呼（与 R30 同一个函数），
在销毁章**之后**的正文字面检索，命中即报；副键也算点名：读者看到别名同样会被提醒「这东西还在」。
一条设定只在最早撞见的那一章报一次（同一条 repeated mention 不该刷屏）。
带 `flashback`/`dream`/`quoted`/`offscreen` 标记的章跳过，没登记 `destroyed-in` 的书整条静默。

恒为 `info`：写"废墟""旧地重提"与忘了它已经毁掉，机器分不开。
`lifecycle['revealed-in']` **不做**——它没有任何生产者（只有模板里的 null 占位），
而且世界条目的名字天然早于正式解释出现，这条判据按构造就是噪声。要"某信息别提前点破"请用 R20。

## L 族：账本登记了、正文从没配合（R29/R30/R31）

K 族查的是"记了又被改写冲掉"，L 族查另一半："记了，正文里从来就没有"。三条共用同一把尺：
`nameForms`（本名 + 别名，一律 ≥2 字）在正文里字面找，口径与 R19/R1 完全一致 ——
判据不一致就会出现"角色页看得见、连续性页看不见"。别名既可能是字符串也可能是 `{text}`，
`nameForms` 两种都认（此前遇到数字别名会抛错，被 `rule-crashed` 吞成整条规则失明）。

### R29 `first-appearance-mismatch`（info，书级）

`character.first`（角色卡上的「首次出场章」，界面能填）此前只被 R15 查"章存不存在"，
内容从不回查。这条比对它：**登记的章更早就露面** → first 写晚了；
**登记的章里没有他任何一个称呼、最早露面在更后面** → first 写早了，或那一章只用代称带过。
两种说法共用一条诊断，指向各自该被修的那一章（前者指向实际露面章，后者指向登记的那一章）。

不查：没填 `first`、卡已关掉、称呼全不足两字、`first` 指向不存在的章（R15）、
**全书从未露面**（那是 R30 的活，一件事只说一遍）。露面只算"现在时"的露面 ——
`flashback`/`dream`/`quoted`/`offscreen` 标记章不参与次序判断，回忆里点一百次名也不算登场。

恒为 `info`：「先声后人」是正当写法，第 1 章提到那个人、第 5 章他才出场，卡上填第 5 章没错。

「写晚了」那一支把算出来的最早露面章放进 `evidence.suggestFirst`，界面上的「照正文改」按钮写的就是它。
另一支（写早了/那一章只用代称）**不给**这个字段：把 `first` 改成正文最早露面那一章，
等于把「本该出场却从头到尾没点名」这件事抹平 —— 那条诊断该被修的是正文，不是卡。

### R30 `entry-never-mentioned`（info，书级）

`unregistered-entity`（R9）的反向：那条查"正文里有名字、账上没档案"，这条查"账上有档案、正文里没名字"。
角色卡与世界条目一起查（称呼取 `nameForms`，世界条目取 `worldForms` = 本名 + `keys` + `secondary_keys`，
与 R28 同一个函数 —— 两条规则问的是「正文里到底有没有提过这个东西」的两面，分家就会出现一条判活着、另一条判从没出现过）。
诊断不指向任何一章（`chapter: null`）—— 没有哪一章可跳，硬指一章反而误导。

两道误报闸门：**已写正文不足 3 章整条不输出**（新书期卡片先建、正文后写，那时报出来全是催命）；
回忆/引文章同样算正文，在旧场景里被点过名就算露过面。关掉的角色卡与世界条目不查。

恒为 `info`：侧面描写、全程用"他""那个地方"指代、留到后面才出场，都长这样 ——
僵尸卡与还没用上的伏笔在机器眼里无法区分，所以它只是一份清理清单。

### R31 `relation-pair-never-together`（info，书级）

`relations.edges` 里 A→B 的边（R19 查称谓越界与双向矛盾），这条问一个 R19 不问的问题：
**这两个人在正文里到底有没有同时出现过**。判据很宽：某一章正文里两方各自的称呼都出现过一次就算同框，
回忆/引文章也算（旧场景里两人说过话同样是正文支撑）。

只查两端都已建档、且各自都在正文里露过面的边：从未露面的归 R30，端点解析不到的归 R15，
两头是同一个角色的自环边不查，**没有 `relations` 的老书整条静默**。端点解析走 `relationgraph` 那一份 ——
边里存的是角色名而本书只有一个此人时照样查得动（AI 抽关系从前存的正是名字，只认 id 等于对这批边闭眼），
名字在角色卡上撞了两个人就不查：不知道该判哪一个。

恒为 `info`：转述式关系（师父只在他人口中出现）、通信、隔空指令都是正当写法。
这条只负责把"账本里亲密、正文里陌生"的边挑出来让人看一眼。

## Q 族：文风基准与漂移（R32）

R22 查的是「这一章像不像 AI」，是全通用词表；R32 查的是另一半 ——
**这一章像不像这本书**。两句都可能成立：一章一个 AI 味都没有，却离作者自己的笔法很远。

### R32 `style-drift`（info，逐章）

数据源是 `src/core/stylefit.js` 那四个数（句均字数、对话占比、段均句数、禁词密度）。
同一个函数被四处调用：生成 prompt 里那一行「基准指纹」、Web 文体页那行数字、
`scripts/nw-style.mjs` 的逐章视图、以及这条规则。所以「prompt 里承诺的基准」与
「检查器按哪把尺查」不可能分叉 —— 这是这批唯一的硬约束，`tests/guards.test.mjs` 守着它。

**基准只认 `book.styleAnchor.chapterIds`（作者勾的）。没勾过就整条闭嘴，一条都不报。**
这一条是刻意的，不是没做完：不勾时顺手取「最近两章」当基准，在长篇里恰好取到漂移最远的那两章，
拿它当尺子等于把已经漂走的笔法盖章成合格标准。所以 CLI 在无基准时照样给数字，
但话术明写「只说明这一章离全书平均有多远，R32 在这种情况下一条不报」。

门槛（`KEYS[].dev`，来路写在 `stylefit.js` 注释里）：

| 键 | 口径 | 越界线 | 为什么是这个口径 |
|---|---|---|---|
| 句均字数 | 相对偏离 | 30% | 本底因人而异（短句流 12 字 / 长句流 40 字），绝对差不通用 |
| 对话占比 | 百分点 | 12 pp | 本底接近 0 时相对偏离会爆炸（1%→4% 就是 +300%，但那不叫漂移） |
| 段均句数 | 相对偏离 | 40% | 同句均 |
| 禁词密度 | 绝对差 | 1.5 处/千字 | 与 R22 的 info 档同值，两条规则对同一个词表不许有两个门槛 |

**两格及以上同时越界才报**。只越一格最常见的解释是这一章本来就要换口气
（动作场面、独白、书信），那不是笔法变了。`confidence` 固定 0.6，severity 固定 `info`，
不进退出码，也不进 `runSelfCheck` 的 actionable 集合 —— 统计数字没有资格命令模型改写自己的句子。

不评的章：基准章自己（不能拿它当尺又告它超标）、带 `flashback`/`dream`/`quoted`/`offscreen`
标记的章（同一批豁免标记在 R23/R26 也用，出处是 `NWRules.EXEMPT_FLAGS`，CLI 视图导入的是同一个 Set）、
正文不足 600 字的章（`NWStyleFit.MIN_BODY`，与「风格样例」注入的合格线同一个常量，两处不许各写一个数）。
那条 600 字按**字数**判（标点不计，`NWText.countWords`），判据只有 `NWStyleFit.qualifies()` 一份：
界面画「可勾与否」、`NWContext` 选样例、指纹入口收章三处都问它，谁都不许再自己比 `body.length`。

指纹按**计数相加后再相除**，不是把各章的比值求平均 —— 后者会让一章 300 字的正文
和一章 6000 字的正文同权。作者 `stylePack` 里关掉某个词组，禁词密度那一格跟着变
（`fingerprint(chapters, NWStylePack.optsFrom(book))`，四处传的都是这一个 opts），
不会出现「界面说基准是 1.2 处/千字、检查器按整包算出 3.1」。

`evidence.basis` 必带四件事，供作者判断这条该不该理：基准是哪几章
（`book.styleAnchor.chapterIds=…`）、基准的体量（几章 / 几字，两章的基准本来就比二十章的抖）、
本章几字、越了几格与门槛原话。

**明确不算**：文笔高低、语义相似度、一个总分。四个数各说各话，作者才有处置权 ——
合成一个分数就是把"这章行不行"的判断权交给统计。

## S 族：卷级压缩的缺口（R33）

前情摘要是三级衰减：最近 12 章逐章给「核心事件」行、再往前 24 章只给章名、更早的只剩一行计数。
卷摘要接管的就是最后那一段 —— 一卷一行，替掉那一卷里几十章的逐章出场。
R33 不查正文，查的是**这套压缩本身有没有被用歪**：作者建了卷，上下文里却什么都没少。

### R33 `volume-gap`（info，书级）

数据源是 `src/core/volumes.js` 的 `recapPlan`（把全书末尾当作当前章），与侧栏「卷」面板、
续写上下文用的是同一份分层 —— 覆盖口径写两遍，就会有一遍和另一遍对不上。
两个窗口（12 / 24）的值也只存在 `NWVolume.RECAP_FINE / RECAP_MID` 一处，`NWContext` 那两个名字是别名。

**只对已经建了卷的书开口。** 卷数为 0 是「还没开始用这套东西」，不是缺陷，一条都不报；
短篇（`book.format=short`）也不报 —— 它的摘要本来就不封顶，卷层根本不参与。

报四种，各自修法不同，混成一句「有缺口」等于什么都没说：

| 成因 | 判据 | 为什么说出口 |
|---|---|---|
| `uncovered` | 超出细窗口与章名层、又没有任何卷盖着的章 | 这些章在上下文里只剩一个计数，模型彻底召回不到 |
| `empty` | 卷框住了几十章，摘要却留空 | 判据一：空卷不盖章，那些章照旧逐章列出，这一卷等于没压 |
| `bad` | 起止章在书里读不出来（被删了 / 填反了） | 判据三：宁可整卷不用，也不按 `order` 猜出一个可能完全不同的区间 |
| `overlaps` | 两卷的区间压住了同一章 | 那段往事在 prompt 里出现两遍，而「压掉 N 章」的 N 是虚的 |

「盖到最后一章的卷」不报：写下一章时它本来就不该注入（摘要不能剧透没写的部分），
那是预期行为，面板上用状态标签说明即可。

恒为 `info`、不进退出码：要不要为一卷补那 120 字永远是作者的决定，
机器只负责说清没压下来的后果是什么。`evidence.basis` 带的是章数、卷数、压掉几章、
重叠几章这些可核对的数，不是形容词。

## T 族：关系账本与那张图（R15 扩、R34）

「关系图谱」这个名字从 P0-2 起就在文档里，可盘上从来没有图：侧栏把边摊成一列卡片，
谁连着谁、哪几块互不相连、哪个角色在网外，全靠作者脑补。更麻烦的是**这条边的两头到底存不存在**
长期没人查：R31 的规格写着「角色 id 解析不到的归 dangling-reference」，而 R15 当时根本不扫 `relations`。

判据只有一份：`src/core/relationgraph.js`。它回答四件事 —— 端点是谁、区间到第几章算活着、
网分成几块、画出来是什么（布局与 SVG 字符串都在 core 里，界面只负责把那段字符串塞进容器）。

### R15 现在也扫关系边（error，书级）

每条边的 `from`/`to` 与 `since`/`until` 都过一遍：端点连不到任何角色（没填、查无此人、同名两个人）
与起止章不在书里，一律 `dangling-reference`。两条口径要说清：

- **写成角色名而卡上名字唯一**算接上，不报 error（AI 抽关系从前存的就是名字），但 R34 会单独提一句；
- **同名两个人**不猜哪一个是他 —— 图上那条线连到谁，作者就会当成账本里说的那个人。

### R34 `relation-gap`（info，书级）

只对**已经登记过关系边**的书开口，一条边都没有就整条闭嘴。报四类，都是「账本自己说得通、
可图上画不出来或画错了」的：

| 成因 | 判据 | 为什么不归 R15 |
|---|---|---|
| `skipped` | 没有 id，或两条边撞了同一个 id | 端点都在，坏的是记录本身；画布上没有这几条线，面板里只剩一颗标签 |
| `self` | 两头连着同一个角色 | 两端都能解析到，只是是同一个人 |
| `reversed` | 结束章排在起始章之前 | 章都在书里，坏的是顺序，不是断链 |
| `byName` | 某一端写的是名字而不是角色 id | 现在连得上，改一次名字就断 —— 趁还能改说一声 |

**不报**「谁在网外」与「图分成了几块」：一条关系都没登记的角色不是缺陷，两条不相干的故事线也不是。
机器替作者决定谁该有关系，换来的就是关检查器。这两件事在面板与图上看得见，不占规则。
端点指向不存在的角色、起止章被删掉这两类归 R15（error），R34 不重复报 —— 一份坏消息说两遍只是吵。
恒为 `info`、不进退出码。

## W 族：单章字数（R35）

「一章该多长」这个数在项目里写过三遍：生成 prompt 承诺 3000-5000，规则按 1200-4000 判，
评分卡又是第三档。三方各自成立，合起来是模型照 prompt 的上限写满 5000 字，回头机检报它超上限 ——
两头都按自己那份数说话，于是谁也不用改。现在只有一处：`src/core/tension.js` 的 `CHAPTER_RANGE`
（长篇那一档 1200-4000 字；短篇那一档 400 字起，上不封顶），`NWTension.chapterRange(book)` 先问
`fmtOf(book)` 归一、再取档；prompt、评分卡（`NWPitch.LENGTH_RANGE` 是同一个对象的别名）、R35 都问它。
「算不算短篇」也收成一处 `NWTension.isShort`，R17/R23/R25/R33/R35 的换挡都从那里走。
那一档怎么说人话也有一个出处（`NWTension.rangeLabel`），文档与 CLI 的 rubric 文案都念它。

**短篇为什么不封顶**：短篇的「章」是一节，长度跟着总字数与投放平台走。
本书的短篇向导自己写着「微型 3k-6k 字，1-2 章」「盐选 5 万字 / 6-10 章」—— 摊到单章最坏 8300 字。
给这一档安一个更小的上限，等于机器天天报一个作者照着界面选出来的计划，
那种诊断不是信息，是噪声。长篇有上限，是因为长篇的章数本来就由作者拆。

### R35 `chapter-length`（info，逐章）

**输入**：`chapters[].body`、`book.format`。**判定**：`NWText.countWords(body)` 落在区间外，
低于下限与高于上限各一条消息（说得清是哪一头、差多少字）。

**误报控制**：
- 正文空着的章不评 —— 还没开写不是缺陷；
- 带 `flashback`/`dream`/`quoted`/`offscreen` 标记的章不评，那几类本来就允许只写几百字；
- 计数一律 `countWords`（汉字逐字、英文与数字整体，**标点与空白不计**），不是 `body.length`：
  后者把标点算成字，对话密的章凭空多出两成，正好撞在最不该误报的那类章上。
  同一口径也管 R17 的评审门槛（改前按字符数、改后按字数，这是一处可见的行为变化）。

**不查**总字数与进度：目标字数摊到每章合不合理是评分卡 `length` 维的事，
它比的是「计划 ÷ 章纲」，R35 比的是「已成稿正文」。两件事的输入都不一样，合成一条就只能两边都判不准。

恒为 `info`、不进退出码：一章多长是节奏与排版的决定，机器只负责报出这一章落在哪一档的哪一头。
过了 4000 字的高潮章不需要谁来判它该拆，所以建议那句给的是「在中间那个转折处拆一刀」而不是「删字」。

## X 族：篇幅档那一格（不是新规则，是上面每一条换挡的共用前提）

W 说「换挡都从 `isShort` 走」，但那一句话当时还写在 19 处各归一遍：三元归一九处（建档落库、库行列表投影、
导出、导入建档、`buildCtx`、预设打包、预设逐格 diff、评分卡取档、CLI 传进评分卡那一格），
拿原始值比 `'short'` 九处（界面五处、`context.js` 两处、「这一档有没有字数目标」的门槛两处 —— 那两处由
下面的 Y 族收掉），
CLI 自己认一遍清单还有一处。写的形状也不止一种（`=== 'short' ? 'short' : 'long'`、
`book.format === 'short' || src.format === 'short' ? …`、`flags.format === 'short' || === 'long' ? …`）。
档位清单另有五份：`workflow.js` 的数组、两份 schema 的 `enum`、建书下拉、CLI 那句 `--format short|long`。
它们当时恰好同义，所以没出事；**恰好**不是测试：谁添第三档、谁把缺档换成短篇、谁漏改一处，
规则就按一档评这一章而界面按另一档收栏，两边各自的测试都能绿。

现在只有 `src/core/tension.js` 一家：

| 句 | 管什么 |
|---|---|
| `FORMATS` | 这一格只有哪几个值。`NWWorkflow.FORMATS` 是它的别名（同一个数组），两份 schema 的 `enum`、建书下拉、CLI 那句 `--format short\|long` 都对着它比 |
| `DEFAULT_FORMAT` | 认不出/没写时落哪一档，现在是 `long` |
| `formatKey(value)` | 归一那一句：**不 trim、不改大小写、不猜**，`'SHORT'`、`'short '`、`'zhong'`、`true` 统统是缺档 |
| `fmtOf(book)` | 库行、`ctx.book`、预设 `fields` 三种形状都问这一句 |
| `isShort(book)` | 唯一的换挡判断，界面也用它 —— 「不等于长篇」不等于「等于短篇」，脏值会被前一句判成短篇，时间线与状态矩阵两栏就此凭空消失 |
| `minFormat(books)` | 评分卡把本书与对照书取更短的那一档，目前只有它用 |

**行为变化只有两处可见**：`nw-pitch.mjs --format` 认不出那个值时，以前悄悄按书自己的档评，
现在会在 stderr 说一句「这一格不参与评分」，退 0 不变。只写 `--format` 没跟值也算认不出，
说的是「(没给值)」而不是参数错误 —— 它确实不影响别的四维。
另一处是 `nw-workflow.mjs pack` 的人读输出：以前逐行打印「这一格现在写着什么」，于是长篇库里
那个遗留的字数目标被报成「全篇字数目标：8000 字」，而打出来的预设根本没有这一格；现在念的是
`NWWorkflow.diffFields` 那一份逐格 diff（与 `check` 同一句、同一行画法）。

`workflow.js` 里剩下两处直接比 `'long'` 是刻意的，不是漏改：那两句问的是「这份预设**声明**了
长篇没有」，不是「这本书算哪一档」（预设没带 `format` 时必须什么都别清，归一成 `long` 反而会把
作者定的目标字数抹掉）。守卫里对这两句另有说明。


`nw-validate.mjs` / `nw-continuity.mjs` 先跑 schema 校验；**不通过则其余规则全部不跑**，
只输出结构违规。这是刻意的：一份字段类型都错的书能派生出几十条假矛盾，
把真问题埋在里面。

## Y 族：这一档有没有字数目标那一格（X 那句的另一半）

X 收掉了「这本书算哪一档」，但那一档还牵着下面这一句：**只有短篇有「全篇字数目标」这一格**。
X 之前它写在三处，而三处不是同一句 —— 建档按「非空就算」存，打包与逐格 diff 按「1000 到十万之间的整数才算」读，
评分卡与进度条各拿原值算。于是：一本短篇存着 500，进度条画出一条 0%、导出去过不了自己那份 schema 的
`target_words.minimum`，而预设说这本书根本没设过目标；一本长篇（update 或导入留下的遗留数）带着 8000，
界面那一格显示「没设」、`pack` 不带它，评分卡的 `length` 维却按 8000 给分。作者看到的是两句相反的话。

现在三句，都在 `src/core/tension.js`（X 那一家，不是第四家）：

| 句 | 管什么 |
|---|---|
| `TARGET_MIN` | 那个数至少多大。出处仍是两份 schema 的 `target_words.minimum`（守卫对着它核），`NWWorkflow.TARGET_MIN` 是它的别名 |
| `TARGET_MAX` | 那个数至多多大（十万：自家承诺过的最贵短篇平台档是盐选约 5 万，十倍只可能是手滑）。出处是两份 schema 的 `target_words.maximum`（守卫对着它核），`NWWorkflow.TARGET_MAX` 是它的别名 |
| `NWTension.targetValue(raw)` | 「这个数本身算不算一个目标」，**不问哪一档**：字符串数字收回整数，小数、负数、`true`、`{}` 一律算没设。用它的两处都知道档是另一回事 —— 预设过闸判的是这份文件写的数，逐格 diff 判的是库里那个数还躺着没有（长篇的遗留数正是「清走它」的依据，所以那句绝不能带档） |
| `NWTension.targetOf(book)` | 「这一档有没有那一格，那个数是多少」。库行的 `target_words` 与 `ctx.book` 的 `targetWords` 两种形状都问它；认不出/缺档算长篇，就没有这一格。调用点六处：建档、导入建档、装配 `ctx`、界面进度条、预设打包、评分卡的 `ctx` 那一头（那一路见下面两段） |

评分卡的两种入参在这条线上是**分开的**，不是漏改：`ctx`（已经写成的书）读的是库里那一格，走 `targetOf`；
`concept`（向导与 CLI 当场填的）读的是「作者打算写多少」，那是规划，长篇也照样能有一个数，不受这一档约束。
把两句并成一句，要么把长篇的规划数判死，要么把库里的遗留数当目标用 —— 守卫里钉着这一句 `isCtx ? … : …`。

**行为变化有四处可见**：

1. 建档：短篇配一个低于下限（或不是整数）的目标，以前照存，现在留空。那本来就是一份过不了自己
   schema 的存档，而界面上没有任何一处能填出这种数 —— 短篇向导给的是平台档位（6k / 2 万 / 5 万）。
2. 导入建档：一本长篇的目录里带着 `target_words`，以前原样进库，现在不落库；导出那一路同理不再把它带出去。
3. 选题评分卡：长篇书那个遗留目标不再参与 `length` 维，如实给「没填目标字数」—— 那句建议本来就写着
   「长篇自己定一个总字数」，以前分数与建议互相不知道对方存在。
4. 侧栏进度条：短篇那个不合法的遗留数不再画出一条谁也算不清的进度条（`pack` 的人读输出同理，它念的是
   逐格 diff 那一份）。

## Z 族：那一档对人叫什么（X 收的是判断，这一批收的是名字）

X 把「这本书算哪一档」收成了 `NWTension.isShort`，但**那一档叫什么**还散在四处，而且不是同一个名字：
逐格 diff 与 `pack` 的人读输出念「长篇连载」（`workflow.js` 自己的一张 `FORMAT_LABEL`）、
R35 那句机检念「长篇」（自己写的三元）、schema 的 description 又是一种写法、
首页书封把「短篇」写成一个字面量。同一本书三个名字，机检面板与首页读起来像三档。

现在只有一张表，跟 X/Y 住同一家（`src/core/tension.js`）：

| 句 | 管什么 |
|---|---|
| `NWTension.FORMAT_LABEL` | 短篇 → 「短篇」、长篇 → 「长篇」。表键与 `FORMATS` 一一对应（守卫核）：加一档忘了给名字，那一档在界面上就是 `undefined`，当场红 |
| `NWTension.formatLabel(v)` | 对人念那一档。对象（库行/`ctx.book`）先问档再查表，其余来路把值本身过 `formatKey` 归一 —— 认不出的值按长篇念，与库里投影同一条判据，所以界面与 CLI 永远不会把 `'SHORT'`、`'zhong'` 原样念给作者。调用点四处：R35 那句 zh、逐格 diff 的 format 行、首页书封标记、建档下拉两个选项 |

两处措辞是**刻意不分**的：预设字段那一格叫「篇幅档」（`FIELD_LABEL`，判据语域），建档弹窗叫「织物规格」（界面语域）；
它们说的是 format 这一个概念，但那是措辞不是判据，并成一处只会让界面上出现「篇幅档」这种术语。

**行为变化有三处可见**：

1. 逐格 diff 与 `pack` 的人读输出：format 行改念「长篇」（以前念一个更长的名字）；脏值不再原样回显
   （`'SHORT'` 以前被 `String(v)` 抄进面板，现在按归一念「长篇」）。
2. 建档下拉：长篇那一项改念「长篇 —— …」。
3. AI 起书向导「题材不限」时，`genre` 这一格不再把档名塞进去当题材（短篇向导写「短篇」、长篇向导写
   「长篇」都曾发生），如实写「不限」—— 那一格是题材表，档名有自己的家。

## D 族：名字与「形」（R36，外加 R22 多出来的两条句式）

对照那两个同类仓库时，有两类判据是它们有、织文没有，而且**数得出来**的：

1. **模型扎堆的人名**。竞品在角色设定那一步直接点名一批「出现任何一个都必须换掉」的名字
   （林晚、顾言、沈清、陆衍……）。织文的去 AI 味包只管**词**，角色卡上的名字从来没人查 ——
   而名字恰恰是读者对一本书的第一记忆。名单住在 `src/core/stylepack.js` 的 `AI_NAMES`，
   **只有一个出处**：R36 拿它查角色卡，`promptBlock` 拿它写进生成前那一行。
2. **「的」字堆叠与一句到底**。这是「形」的判据，与「三短句连击」同一个形状（能数、能回查原文），
   所以进 `PATTERNS`、由 R22 一起报，不另开规则号。两个门槛都刻意比竞品那句「每句『的』不超过两个」宽：
   中文叙述里三个「的」是常态，按竞品那个数天天响的检查器一周就会被关掉。

### R36 `ai-name-clash`（info，书级）

**输入**：`characters[].name/aliases/enabled`。
**判定**：本名或任一别名**整格等于** `AI_NAMES` 里那一个 → info。
**误报控制**：
- 整格相等而不是包含 —— 「林晚风」不该被「林晚」挑出来，那是另一个名字；
- 别名一起查：作者常先定一个正经本名，正文里却用那个扎堆的称呼；
- `enabled=false` 的卡不查；
- 每本书最多报 `NAME_CLASH_MAX = 3` 条：张张都中说明的是整体起名风格，逐张念一遍只是刷屏；
- 恒为 info，永不进退出码 —— 名字撞车不是前后矛盾，同名、谐音、致敬都是正当写法。

**与 R30 的分工**：R30 问「建了档的人在正文里露过面没有」，这条问「这个名字是不是那一批」。
零章正文也能报，因为换名最省力的时刻就是建档那一刻。

**可见的行为变化**：R22 的句式类别从 5 类变 7 类，「两类及以上即 warn」这条门槛没动，
所以一句里堆了五个「的」、又恰好连着三短句的章，以前是 info、现在是 warn。

## llm: 规则（机器做不了，需模型判断）

这些**不实现**在 `rules.js` 里，由 agent 自己判断，但必须守
`SKILL.md` 里的三条（`llm:` 前缀、`evidence.quote` 可字面回查、`confidence<0.7` 降 info、
永不计入退出码）。

| 名字 | 场景 |
|---|---|
| `llm:motivation-drift` | 角色行动与已确立的目标/性格矛盾，但不是事实错误 |
| `llm:voice-break` | 对白口吻跳出该角色已建立的说话方式 |
| `llm:semantic-payoff-match` | 某处描写看起来算某条伏笔的回收，建议回填 `payoff.chapter` |
| `llm:world-rule-violation` | 情节与 `constant` 类世界规则隐性冲突 |
| `llm:timeline-implicit` | 从"三天后""入夜"等叙述推断时间流逝，只能产 `implied` 置信度 |

不许自创规则名。超出上表的问题，用自然语言写在报告里，不要伪装成规则。

## 尚未实现的机器规则

写在这里以免被误认为"检查过了"：

- `location-teleport`（同刻瞬移）：需要最小行程表，v1 未做。
- `restricted-address-term`（称谓越界）：需要可靠的说话人归属，误报率高，v1 未做。
  注意这**不等于** R19 的称谓检查：R19 只在作者登记了 `address` 时比对正文里出现的
  其他称谓词，不判断"谁在说话"，所以覆盖不到"该叫师兄的人当面叫了师父"这类越界。
- 世界书 `recursive_scanning`：**已实现，两层封顶**（第 1 层扫正文，第 2 层只扫已注入条目的正文）。
  再深就会顺着一条设定把整本书拖进 prompt；`bible/world/_index.json` 里那三个扫描字段
  由 `NWStory.loreIndexConfig()` 派生，不是本书的可调开关。

物品失而复得原本是这条清单里的 `item-state-contradiction`，现已由 R18 覆盖，
但只在状态矩阵记了的前提下生效——矩阵本身的完整度靠作者维护。
关系矛盾（原 `relation-contradiction`）现已由 R19 覆盖，同样以作者登记的关系边为前提。

R6 已实现，但它只在锚点填了 `day` 之后才生效：没登记时间的章节它看不见。
锚点稀疏时覆盖面小，这是能力边界而不是缺陷——宁可少报也不要凭猜报错。

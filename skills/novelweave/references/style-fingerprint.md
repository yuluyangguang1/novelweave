# 文风指纹与基准章（style fingerprint）

一句话：**把「这本书自己的笔法」量成四个数，并且让作者说哪几章算数**。

R22（`ai-flavor`）用的是全通用词表，查的是「像不像 AI 写的」；这一族查另一半 ——
「像不像你自己」。一章可以 AI 味为零却已经不像这本书了，那两个检查器说的是两件不同的事。

判据只有一份：`src/core/stylefit.js`。生成 prompt 里那一行「基准指纹」、Web 端
「文体规则」页那行数字、机检 R32、`scripts/nw-style.mjs`，四边调的是同一个函数，
门槛也只在 `KEYS[].dev` 里写了一次。改判据就是改那个文件，会红的测试：
`tests/stylefit.test.mjs`（纯函数）、`tests/rules.test.mjs`（R32 每格正反夹具）、
`tests/guards.test.mjs`（不许在界面、prompt 或 CLI 抄第二份）。

## 四个数

| 键 | 含义 | 越界口径 | 门槛 |
|---|---|---|---|
| `sentAvg` | 句均字数 | 相对偏离 | 30% |
| `dialogue` | 对话字数占全章比例 | 百分点 | 12 pp |
| `paraSent` | 段均句数 | 相对偏离 | 40% |
| `cliche` | 禁词密度（处/千字，来自内置去 AI 味包） | 绝对差 | 1.5 |

三条口径不统一是故意的：句均/段均的本底因人而异（短句流 12 字、长句流 40 字），
只能用相对差；对话占比接近 0 时相对差会爆炸（1%→4% 就是 +300%，但没人把这叫漂移），
只能用百分点；禁词密度与 R22 数的是同一张词表，门槛必须与那边的 info 档同值。

几章合成一份指纹时**计数先相加再相除**，不是各章比值求平均 —— 后者让一章 300 字与
一章 6000 字同权。**没有总分**：四个数各说各话，作者才有处置权；合成一个分数等于把
「这章行不行」交给统计。明确不算的还有文笔高低与语义相似度。

## 基准章 `book.styleAnchor.chapterIds`

作者勾的那几章（1–2 章就够）同时决定两件事，这是它存在的全部意义：

1. **生成时注入哪几段正文当样例** —— `NWContext.stylePool()` 返回
   `{source:'anchor'|'auto'|'anchor-lost', list}`。没勾时按「目标章之前最近的两章」自动取样，
   那在长篇里恰好是漂移最远的那两章。
2. **R32 拿哪几章的指纹当尺子** —— 没勾过就整条闭嘴，一条都不报。
   自动取样的那两章可以当样例，但不能冒充标准。

`anchor-lost` 是第三种情形：作者勾过，可那几章正文后来都变短到不足 `MIN_BODY`（600 字）。
生成时退回就近取样，R32 仍然不报（基准还是不存在），界面与 CLI 都会明写退回了。

「够不够 600 字」只有一处判据：`NWStyleFit.qualifies(body)`，按**字数**算（标点不计，
`NWText.countWords`）—— 与界面上每章那个「N 字」、与 CLI `--json` 里的 `minBodyWords` 同一个数法。
这一条曾经按 `body.length` 判（字符数），于是一章 480 字的正文在界面里显示「480 字」却被画成可勾，
而规则话术写着「正文不足 600 字的章不参与」。选样例的 `NWContext.isEligible`、指纹入口
`fingerprint()`、界面清单那三处现在都从 `qualifies` 取判据，守卫不许任何一处再自己比长度。

同一份 `stylePool` 也被「文体规则」页与 `nw-style.mjs` 用，所以「屏上说的样例是谁」
和「模型真读到的」不会是两个答案。注入顺序是**先收样、再拿实际在场的那几章算指纹**
（`pickStyleExemplars`）：反过来就会出现「样例只剩一章、那一行却说 2 章 / 1746 字」——
数字描述不到作者眼前读到的东西，那行就只是装饰。指纹行自己也要占预算，
所以样例那节的预算先给它留出 `FIT_LINE_RESERVE`（300 字节）再收。

**勾中的正文会原样进 prompt 当样例**：这是特性不是泄漏，但请作者自己挑——
那几章别人都会读到。

## 命令

```
node scripts/nw-style.mjs [bookDir] [--json]              # 整本指纹 + 逐章偏离 + 注入预览
node scripts/nw-style.mjs keys [--json]                   # 四格与门槛（从包里现取）
node scripts/nw-style.mjs anchor [bookDir] --set ch-001,ch-002 [--json]
node scripts/nw-style.mjs anchor [bookDir] --clear [--json]
```

- 默认子命令是 `fit`：`nw-style.mjs <bookDir>` 直接给整本视图。
- `anchor --set` 写的就是 `book.styleAnchor.chapterIds`，与 Web 端勾的是同一个键；
  章 id 不在书里会被拒绝并列出可写的清单，拒绝时一个字都不落盘。
  `--clear` 是**删掉这个键**而不是留 `null`（schema 里 `styleAnchor` 不可为 null，
  留 null 等于给这本书白添一条 error）。
- 逐章那一栏的 `role` 只有四种：`baseline`（基准，不评自己）、`too-short`（不足 600 字，
  不进指纹，`words` 给 0 而不是编一个数）、`exempt`（带 `flashback`/`dream`/`quoted`/`offscreen`，
  名单取自 `NWRules.EXEMPT_FLAGS`，与 R32 同一个 Set）、`chapter`（参与比对）。
- 越界**两格及以上** R32 才报，理由：只越一格最常见的解释是这一章本来就要换口气
  （动作场面、独白、书信）。CLI 里一格也列出来，但它只是数字，不是结论。
- 退出码：0 · 2 用法/参数错 · 5 读盘错。**偏离永不阻断**，且 `--json` 那份里
  `baseline.source` 一定要读：`auto` 时下面那些「越 N 格」说的是「离全书平均多远」，
  不是「离你的标准多远」。

## agent 该怎么用它

- 作者说「我写着写着不像这本书了」→ 先 `keys` 讲清四个数各是什么，再跑 `fit`。
  没勾基准就先让他勾（`anchor --set` 或网页上勾），否则你手上那份数字没有标准。
- 不要替作者挑基准章。哪几章代表这本书的笔法只有他知道；机器只能看出「哪几章彼此很像」。
- R32 是 `info`、`confidence` 固定 0.6，永不进退出码，也不进生成后自检的 actionable 集合。
  看到它就照原样报给作者，**不要**为把它消掉去改写句子。
- 报告漂移时把 `evidence.basis` 那四件事一起给出（基准是哪几章、几章 / 几字、本章几字、
  越了几格与门槛）。两章的基准本来就比二十章的抖，缺了体量数字作者没法判断这条值不值得理。
- 作者在这本书里关掉过某个词组（`book.stylePack.disabled`）时，禁词密度那一格跟着变 ——
  指纹按 `NWStylePack.optsFrom(book)` 的同一个 opts 算。若他整包关掉，`cliche` 会归零，
  这时「越两格」门槛更难达到，这是正确的行为，不是 bug。

## 网页上在哪

侧栏「文体规则」页：上半是去 AI 味词组开关（`book.stylePack`，见 `prose-handoff.md`），
下半是「文风基准章」勾选清单 + 那四个数。正文不足 600 字的章会被画成不可勾并写明原因；
「先只勾最早那一章」只改屏上的勾态，按「保存」才落库 —— 落库后数字才跟着重算。

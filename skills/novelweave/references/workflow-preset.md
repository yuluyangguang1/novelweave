# 工作流预设（作者之间搬的那几格）

判据唯一出处：`src/core/workflow.js`（模块 `NWWorkflow`）。
对外形状声明：`schemas/workflow.v1.json`。
网页入口：侧栏「工作流」页。命令行：`scripts/nw-workflow.mjs`。
**这一份文档只说怎么用它；哪三格能走、什么算坏，一律以 core 那份为准。**

## 它搬什么

预设只带那三格设置（清单出自 `NWWorkflow.FIELDS`，界面、CLI、schema 都问它要）：

- **篇幅档** —— 短篇还是长篇。它决定上下文与规则阈值怎么换挡。只有两个值，出处是
  `NWTension.FORMATS`（`NWWorkflow.FORMATS` 是它的别名，两份 schema 的 `enum` 与建书下拉都对着它比）；
  对人念那一档只有 `NWTension.formatLabel` 一个出处 —— 逐格 diff 那一行的「短篇/长篇」就是它，
  认不出的值按长篇念，不许把脏值原样回显。这一格在两边规矩不同：
  **预设**里写一个认不出的档，过闸当场判坏，不会静默落回某档；
  **书**那一格认不出的写法由 `NWTension.formatKey` 归成长篇
  （不 trim、不改大小写）。
- **全篇字数目标** —— 只给短篇用；「这一档有没有那一格」与「这个数本身算不算一个目标」各有一句，
  都在 `src/core/tension.js`：打包那一路问 `NWTension.targetOf`（短篇才看那个数），
  认不出档与长篇一律留空；上下限 `NWTension.TARGET_MIN` / `TARGET_MAX` 与书存档用的是同一对数
  （见 `schemas/story-bible.v1.json` 的 `book.target_words.minimum` / `maximum`），
  两处不同就会出现「导得出去、进不来」。
- **去 AI 味规则包** —— 整包开关、关掉哪几组禁词、作者自添的禁词。

明确不进预设（`NWWorkflow.NOT_SHARED` 里各带一句为什么，界面与文档都引那两句）：

- 基准章 `styleAnchor` —— 原话照抄，别处不许各写一遍：它记的是这本书里若干章的身份证，换一本书那些 id 就指不到东西 —— 那是身份，不是设置。
  所以**换书后基准章要重新勾**（`nw-style.mjs anchor`），这不是遗漏。
- 书名 / 类型 / 简介：这一本是什么书，不是怎么写书。

## 文件长什么样

```json
{
  "kind": "novelweave.workflow",
  "version": 1,
  "name": "我的短篇流程",
  "note": "作者留的话，随便写",
  "fields": {
    "format": "short",
    "target_words": 8000,
    "stylePack": { "enabled": true, "disabled": ["aphorism"], "extraBanned": ["属实"] }
  }
}
```

`fields` 可以是三格的任意子集（只带一格也算一份预设）。它是**独立文件**，不进 `.novelweave/`：
项目那套磁盘格式只认自己的树，预设塞进去等于给自己加一个没人读的目录。

## 一份外来预设能信到哪一步

`NWWorkflow.normalize` 把输入分成三堆，**每堆都要能说出口，一条都不许悄悄丢掉**：

| 哪一堆 | 怎么说 | 后果 |
|---|---|---|
| `errors` | kind / version 不对、顶层不是对象、一格设置都没有、**认不出的键** | 整份拒收。带没见过的高阶设置的文件用半份下去，分享者以为那套已落地、接收者看不出没落地的那部分 |
| `bad` | 篇幅档写了别的值、字数目标不是整数或出了上下限、规则包子键认不出、点了这版程序没有的禁词组、长篇配字数目标 | 那一格点名说原因；**整份也不应用**，改对了再谈 |
| `fields` | 过了闸的格 | 才谈「会改哪几格」 |

还有一件事要说清，它与闸不同：某一格合法，但**在这本书里落不下**。
只带字数目标的预设遇到一本长篇就是这种（预设没换篇幅档）。core 在 `diffFields` 的
那一行上写 `blocked`，`patchOf` 于是不会带上它；界面与 CLI 不许把它画成「要改」，
也不许报成「这一本已经就是这套工作流」—— 落不下不等于已经对了。

反方向是同一句判据（`LONG_NO_TARGET`）管着的另一件事：预设把篇幅档换成**长篇**时，库里那个字数
目标要**如实清掉**。`diffFields` 在那一行上写 `clears`，它 `changed` 为真（所以会画箭头），
`patchOf` 对它写 `null` —— 与建档那一路留空同一个表示法，导出时那一格会被整个丢掉。
不清就是另一句假话：面板按 `pack` 说话，显示「（这一格没设）」，进度条不画，而选题评分卡还在按
那个旧数算分 —— 作者看见的是空的，实际吃到的是有数的。
**预设没带 `format` 时一格都不许多清**：只动禁词组的那份预设不许顺手抹掉作者自己定的目标，
「应用只改它带来的格」这句话就是这么保住的。

## 怎么写库

只有一条路：网页那张**逐格 diff 的确认框**（现在 / 预设 / 会不会变，每行由 `NWWorkflow.diffFields`
算，补丁由 `NWWorkflow.patchOf` 算）。一格都没变就一个字都不写。
`nw-workflow.mjs check` 只报告会改哪几格，**不写库** —— 命令行拿到的是别人写的设置，
没人当场点头就落盘，正是这套预设要避免的那件事。

「只有一条路」说的是**写库那一步**，不是预设文件的来路：侧栏「工作流」页上「改字数目标」那一格
也能当场填数（短篇才有输入框；长篇只说 `LONG_NO_TARGET` 那一句），填的那个数是被当成
**一份只带这一格的预设**交进 `NWWorkflow.normalize` 的，过了闸才进同一张确认框。
所以越界与不是整数的数照样进不了库，而 blocked / clears / 「一格都没动」那三条语义一处都不少。
这一路目前**只能改，不能撤**：填空会被闸如实判坏（「空着不算撤掉这一格」），要撤掉那一格
只能应用一份把篇幅档换成长篇的预设。

## 命令行

```
node scripts/nw-workflow.mjs keys [--json]                       # 哪三格能走、哪几格明确不走
node scripts/nw-workflow.mjs pack [bookDir] [--name X] [--out f] # 从磁盘上的书打包，并过自己那道闸
node scripts/nw-workflow.mjs check <preset.json> [bookDir]       # 过闸 + 逐格说会改哪几格
```

退出码：0 预设能用 · 1 预设不能用（原因逐条打在 stdout）· 2 用法错 · 5 读不到文件。
`pack` 打完会立刻 `normalize` 自己一遍：导得出去、进不来，就在这一步红给你看。

## agent 该怎么说话

- 收到坏预设：把 core 那几句原话逐条念给作者，**不要替他删掉认不出的键再导**。
  那等于把「我们这版没实现」说成「你这份写错了」。
- 收到只带某一格的预设：先说清它只搬这一格，其余照旧（CLI 那一行「这份预设不带…」）。
  唯一的例外是篇幅档换成长篇时，那个字数目标会被一起清掉 —— 「照旧」那一行里不会有它，别自己补。
- 应用完之后：基准章要重新勾（`nw-style.mjs anchor`），预设里没有它，也不该有。
